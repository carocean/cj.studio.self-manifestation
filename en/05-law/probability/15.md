# The Reachability Form of Probability

## Section One　Purpose, Form-Kind and the Single Task

Given an already constructed probability operating substrate, an explicit initial state, a frozen identity of the Probability candidate, frozen permitted inputs, running modes and operation set, and a probability-side target declared in advance, to prove whether there exists a finite legal path hitting this target from this initial state.

Form-kind: Reachability Form, auxiliary form. By the specification of the Reachability Form in the Canon Chapter, the construction is already given (the fourteenth text); here the initial state and the permitted set are frozen first, and then the path construction, the bound on the step count, the reachability theorem and the strength are given.

The core output is support reachability:

SuppReach\_Ξ^Prob(X\_0; G\_Θ) ∈ {1, 0, ⊥}

What it asserts is "there exists a finite legal path". It is not controllable reachability (CtrlReach), not "all permitted paths necessarily arrive", nor "arriving with probability one".

What probability is, how it acts and how it changes are not studied anew here; the meanings of probability qualification, current action and cross-time dynamics are all taken over from the sealed first to fourteenth texts. Here it is asked only: starting from a specific initial state, can one legally walk to those already defined probability-side targets.

## Section Two　Upstream Input and Boundaries

### 2.1 Upstream input

The first to third texts: probability qualification N\_P = D ∧ B ∧ R (the common binding written B so as not to be confused with the Continuation-Position C).

The fourth to sixth texts: current action ProbabilityAct.

The eleventh to thirteenth texts: cross-time dynamics N\_PDyn, the unit-level criterion of ActDyn, RateDyn, the three-way division of QualStructDyn, qualification contact, the same-witness key SamePDynBind, layered coverage and the three-valued discipline.

The fourteenth text: the reference construction Spec\_ProbB^ref = Augment(F\_ref, A\_Prob^run, A\_Prob^read), and its sealed reference implementation (probability\_running\_base\_v1\_0.py, SHA-256 = 187a9305db39fdb141502d64a79763427f1d7dda7bc8d8eb2c71bc69683f482a). It is consumed here directly, not modified.

### 2.2 Boundaries

Constructibility ≠ Reachability: the fourteenth text shows that running systems satisfying the conditions can be constructed; here it is shown whether one can legally walk to a target from some X\_0.

Reachability ≠ Source: that a path can reach Probability = 1 does not mean that the observed first formation as Probability in reality was produced by this history; the actual first source belongs to The Source Form of Probability.

Reachability ≠ Necessity: that there exists one path is not that all paths, almost all paths or necessarily arrive.

Reachability ≠ Stability: that there exists a path of one 0 → 1, 1 → 0 or recovery is not persistence, a recovery time limit, or stability on all legal trajectories; these belong to the sixteenth text, The Stability Form of Probability.

Reachability ≠ Implementation: reachability here is reachability in the running model, not something already built under real materials, resources and engineering constraints.

Probability ≠ Pr(reach): the "probability" spoken of by the Probability Group-Form is a Law organization; "what is the probability of reaching some target" is another matter. Reachability here is that there exists a path, not a probability value.

## Section Three　Task Specification, Initial State, Target and Permitted Set

### 3.1 Task specification

Ξ\_PR = (Spec, Prot, X\_0, χ̄\_P, G\_Θ, Adm\_PR, Γ\_reach)

Spec: the constructed running specification. The current bearer of the positive construction is Spec\_ProbB^ref.

Prot: the running protocol (run, branch and protocol identifiers stay unchanged along the path).

X\_0: the explicit initial state of the present task (3.2).

χ̄\_P: the cross-time identity anchor of the Probability candidate (3.3).

G\_Θ: the target declared in advance (Section Four).

Adm\_PR: the frozen permitted set (3.4).

Γ\_reach: the frozen evaluation protocol, prescribing in advance the rule of selecting evaluation points, by which the anchoring map a\_Γ is determined (4.3).

### 3.2 Initial state

The initial state of every task is given from the empty substrate by a declared construction prefix (X\_empty, X\_P, X\_idle, X\_act, X\_new, X\_bind, X\_bear of Appendix A). Here only the final state of the prefix is taken as the initial state, and the prefix is not counted in the reachability path; the prefix itself also consists wholly of legal routes.

### 3.3 Candidate identity anchor

χ̄\_P = (𝒫, C, 𝔯\_P, π\_role, CandidateID)

The current V\_P is not frozen into the identity: DimStructDyn already allows V\_P(t) to change, and if it were written into the identity, the target of a new dimension entering the probability organization would be blocked in advance. Likewise, the set of carriers that have currently formed Laws is not frozen.

C, 𝔯\_P, π\_role, CandidateID must be fixed. π\_role may not be modified along the path in order to obtain RateBearingStructDyn.

### 3.4 Permitted set

Adm\_PR = (U^adm, M^adm, O^adm)

U^adm: permitted external inputs, that is, the specific routes allowed to be driven from outside (some carrier via some coordinator, or some out-of-domain path);

M^adm: permitted running modes (externally driven, endogenous continuation, idle tick);

O^adm: permitted field operations (availability, masking, freezing, unfreezing, channel, kernel wiring).

That the operating substrate has some operation is not that the present task permits it; every task freezes the subset it really permits.

Explicitly prohibited: directly rewriting g, d, rep, BindSed; directly writing D, B, R, Probability, Rel\_ρ, ProbabilityAct, RateDyn, QualStructDyn; modifying π\_role during running; changing CandidateID, C or the rate domain; rewriting logs to manufacture witnesses; keeping the original reachability conclusion after changing the target.

Readers are not operations: invoking a reader produces no successor (Appendix B, reader\_is\_not\_an\_operation).

## Section Four　Reachable Prefixes, Target Nodes and Legal Successors

### 4.1 The family of targets

Θ\_Prob = { Prob, Act, Start, Continue, Stop, Rate, Dim, Bind, Bear }

The nine classes are only the types of target a reachability task can choose, not nine new items of probability ontology.

State-level target: G\_Prob = { X: Probability(X) = 1 }.

Event-level target: G\_Act = { evaluation point X\_k: the action reading of the event of the tick ending at that point is 1 }.

Evaluation-step-level targets: the remaining seven classes fall on adjacent evaluation steps and are not written as "X satisfies RateDyn = 1". Taking

Z\_k = (S\_k, I\_k, S\_{k+1}), together where necessary with the event record of that step Z\_k⁺ = (S\_k, I\_k, ℰ\_k, S\_{k+1})

as the carrier of the target:

G\_Start = { Z\_k: ActDyn\_k = Start }; G\_Continue, G\_Stop likewise;

G\_Rate = { Z\_k: RateDyn\_k = 1 }; G\_Dim, G\_Bind, G\_Bear correspond respectively to DimStructDyn, BindStructDyn, RateBearingStructDyn being 1.

Z\_k is only the carrier of the target in the reachability proof, not a new ontological object of probability.

### 4.2 Two kinds of step

Underlying running steps: every permitted external driving, endogenous continuation, idle tick or field operation in the path; the number of running steps of the path is written H\_run.

Evaluation steps: one step between adjacent evaluation points given by the frozen evaluation protocol Γ\_reach; the number of evaluation steps contained in the path is written H\_eval. Z\_k, legal successors and the rank of Section Six are all counted in evaluation steps.

When every tick is an evaluation point, H\_run = H\_eval; when evaluation points are sparser, one evaluation step can contain several running steps (G\_Bear of Section Ten: H\_run = 18, H\_eval = 1). Below, whenever a number of steps is spoken of, it is stated which kind.

4.3 Mapping from running paths to evaluation prefixes

The underlying running path γ = (X\_0, ζ\_0, X\_1, …, ζ\_{H\_run−1}, X\_{H\_run}) and the evaluation prefix π use two sets of indices, their correspondence given by the anchoring map:

a\_Γ: {0, …, H\_eval} → {0, …, H\_run}, a\_Γ(0) = 0, 0 = a\_Γ(0) \< a\_Γ(1) \< … \< a\_Γ(H\_eval) ≤ H\_run

a\_Γ is wholly determined by the Γ\_reach frozen in advance. Accordingly define

π\_Γ(γ) = (X\_0; Z\_1, …, Z\_{H\_eval}), Z\_k = ( X\_{a\_Γ(k−1)}, I\_k, X\_{a\_Γ(k)} ), I\_k = { ζ\_r: a\_Γ(k−1) ≤ r \< a\_Γ(k) }

When event records are needed, extend to Z\_k⁺ = ( X\_{a\_Γ(k−1)}, I\_k, ℰ\_k, X\_{a\_Γ(k)} ), ℰ\_k being the event records of the running steps in I\_k.

The endpoint of the path enters π only when Γ\_reach already lists it as an evaluation point; the endpoint is not added ad hoc to the evaluation points because the path ends there. If a\_Γ(H\_eval) \< H\_run, the running steps after the last evaluation point do not constitute an evaluation step.

The Γ\_reach used here are all equidistant rules: a\_Γ(k) = k·m, m being the frozen evaluation interval. Tick-by-tick evaluation takes m = 1; G\_Bear takes m = 18, so a\_Γ(0) = 0, a\_Γ(1) = 18, giving one evaluation step spanning t = 18 → 36. certify in Appendix A takes evaluation points by this rule and outputs a\_Γ in the certificate (field a\_gamma); the control path\_end\_not\_promoted in Appendix B verifies that the endpoint is not promoted: a 10-step path under m = 4 obtains only the evaluation points 0, 4, 8.

### 4.4 Legal prefixes and legal successors

A finite legal prefix π = (X\_0; Z\_1, …, Z\_j).

Next^adm\_PR(π) is: the set of next evaluation nodes produced from the end of the current legal prefix through the frozen Adm\_PR and the normal dynamics of the operating substrate, such that after extension the whole prefix is still legal. Legality checks at once: the same run, the same branch, the same candidate anchor, operations belonging to the permitted set, no direct writing into target readings. Evaluation-step-level targets further require that step to have SamePDynBind = 1, and the coverage at each layer needed by the target reading to be 1 (the twelfth and fourteenth texts); readings caused by insufficient coverage do not serve as evidence of hitting.

## Section Five　Support Reachability and Path Certificates

### 5.1 Definition

SuppReach\_Ξ^Prob(X\_0; G\_Θ) = 1 if and only if there exists a finite running path

γ = (X\_0, ζ\_0, X\_1, …, ζ\_{H−1}, X\_H), H \< ∞

(H being the number of running steps H\_run) such that PathLegal(γ), InputAdmissible(γ), AnchorFixed(γ), NoDirectTargetWrite(γ) are all 1, and TargetHit\_{G\_Θ}(π\_Γ(γ)) = 1 (π\_Γ(γ) obtained by Γ\_reach according to 4.3); evaluation-step-level targets further require the hit step to have SamePDynBind = 1 and basic coverage 1.

The path certificate CertReach^Prob(γ, G\_Θ): checks admissibility and anchor invariance step by step, recording separately the positions of admission failures and of anchor changes; and records at the same time the initial state, the declared and the actually executed numbers of running steps, the number of evaluation steps, the anchoring map a\_Γ, and the hit state or evaluation step (together with its evaluation index and running index) and its three-valued readings. It is a proof certificate and does not enter the ontological definitions of Probability, ProbabilityAct or ProbabilityDyn.

### 5.2 Three values

1: it suffices to give one complete, legal, finite hitting path.

0: it must be proven that for every H \< ∞ and every permitted path γ ∈ Paths\_H^adm, TargetHit\_{G\_Θ}(π\_Γ(γ)) = 0.

⊥: all other cases. No hit in finitely many attempts, no hit within some step budget, some material of the operating substrate unobtainable — all can only be recorded ⊥, not 0. Section Eleven sets out this discipline separately.

## Section Six　Theorem of Finite-Rank Support Reachability

### 6.1 Theorem One

Let D^π\_Θ be the set of legal prefixes, ρ\_Θ: D^π\_Θ → ℕ. If

(i) ρ\_Θ(π) = 0 ⇒ TargetHit\_{G\_Θ}(π) = 1;

(ii) ρ\_Θ(π) \> 0 ⇒ there exists Z′ ∈ Next^adm\_PR(π) with ρ\_Θ(π ⌢ Z′) \< ρ\_Θ(π),

then SuppReach\_Ξ^Prob(X\_0; G\_Θ) = 1, and there exists a hitting path whose number of evaluation steps H\_eval ≤ ρ\_Θ(π\_0).

Proof

Starting from π\_0, as long as ρ \> 0, take by (ii) a legal successor making ρ strictly decrease. ρ takes values in the natural numbers and reaches 0 after at most ρ\_Θ(π\_0) strict decreases; by (i) the target is then hit. Every step is a legal successor, so the whole path is legal and finite, and the number of evaluation steps does not exceed ρ\_Θ(π\_0). □

Here ρ\_Θ is defined on the whole declared domain of legal prefixes D^π\_Θ, and condition (ii) must hold for every prefix in this domain with ρ \> 0.

### 6.2 Strength

Theorem One gives only that there exists one path; it implies neither that all paths arrive nor that they arrive with probability one. When the running specification is deterministic (the reference implementation of the fourteenth text is deterministic), "there exists a path" is choosing a sequence of actions in the permitted set; if a future running specification itself carries a stochastic kernel, "arriving with positive probability" or "arriving with probability one" can be reported separately, but that is not the definition of reachability here.

### 6.3 Relation to explicit path proofs

Theorem One gives a general finite-rank sufficient condition. The nine instances of Sections Seven to Ten do not depend on Theorem One for obtaining reachability, but, along the "path construction" route permitted by the Canon Chapter, obtain SuppReach = 1 directly from complete, finite, legal paths; the number of steps of the listed paths directly gives the upper bound on the number of steps. The ρ(π\_j) = H − j defined only along one chosen path is not a rank function defined on the whole domain of legal prefixes and is not used to pass as an instantiation of Theorem One. If in future a rank function satisfying the two conditions of 6.1 can be constructed on the whole declared domain of prefixes, a bound of the same kind or a stronger unified bound can be obtained from Theorem One; this version makes no such additional claim for the nine instances. For three classes of target among them, a lower bound equal to the upper bound is further given, obtaining the exact shortest number of steps under this specification and this permitted set.

## Section Seven　Reachability Instance of Probability Qualification

Task G\_Prob

X\_0: the empty substrate (candidate dimensions Left, Right, NewRoute, two carriers per dimension, coordinators G0, G1, decay rate 0.0005), V\_P = ∅, Probability = 0.

Adm: M = {externally driven}, U = {Left1 via G0, Right1 via G0}, O = ∅.

Γ\_reach: every tick is an evaluation point.

Path: Left1 and Right1 alternating for 4 rounds, 8 running steps in all (H\_run = H\_eval = 8).

Certificate: all 8 steps are within the permitted set and the anchor is unchanged; at step 8 Probability = 1, all earlier evaluation points being 0. So SuppReach = 1. At step 8 the bindings of G0 to the two dimensions have each formed a Law through 4 sedimentations, B = 1; the rate-bearing certificate holds, R = 1.

The fourteenth text uses a formation history of 14 steps (plus two rounds of asymmetric walking of Left1) to establish the baseline for its subsequent tests; here, from the same empty initial state and the same permitted set, the prefix of its first hit is taken as the formal certificate. A construction history is not the shortest reachability certificate.

Shortest number of steps: the upper bound 8 is given by the path above. What the lower bound depends on are all running facts of the reference construction of the fourteenth text, confined to the Adm frozen here and Spec\_ProbB^ref, not new dynamic rules:

(a) an externally driven route adds one sedimentation each only to the one carrier and the one coordinator on the route, and to the one binding pair they make up;

(b) a path starting from g = 0 has, after n sedimentations, g ≤ 1 − 0.78ⁿ; at n = 3 it is about 0.525, below the threshold 0.55, so forming a Law needs at least 4 sedimentations.

In the Adm frozen here, each step can execute only one of Left1 via G0 or Right1 via G0, so each step adds at most one sedimentation to one of the two target carriers; Probability = 1 requires each of the two dimensions to have one carrier that has formed a Law, and the two carriers each need at least 4, so any permitted hitting path has at least 8 running steps. The shortest number of steps is exactly 8.

## Section Ten　Reachability Instance of the Rate-Bearing Organization and the Implementation-Copy Contrast

Task G\_Bear

X\_0: the fork substrate with decay rate 0, Left1, Right1, NewRoute1 each walked 6 times via G0 (t = 18), one formal carrier per dimension. Taking decay rate 0 is the choice of reference implementation made by the fourteenth text to construct exact SameRel.

Adm: M = {externally driven}, U = {Left2 via G0, Right2 via G0, NewRoute2 via G0}.

Γ\_reach: with t = 18 as the initial evaluation point, an evaluation point is set after every 18 running steps thereafter. This is an evaluation rule defined in advance, not designating the endpoint of some path as an evaluation point after seeing it succeed. The certificate given therefore uses the adjacent evaluation points t = 18 and t = 36.

Path: Left2, Right2, NewRoute2 in turn for 6 cycles, 18 running steps in all. The evaluation protocol produces only one evaluation step spanning t = 18 → 36: H\_run = 18, H\_eval = 1. 18 is the number of steps of underlying permitted operations, not 18 evaluation steps.

Certificate: on the evaluation step (18, 36) the raw weights satisfy w⁺ = 2·w⁻, SameRel = 1; the formal rate-bearing organization changes from a single hyperedge to eight hyperedges; RateBearingStructDyn = 1, SamePDynBind = 1. The upper bound on running steps is 18; no lower bound is given here.

Note: if the evaluation points are changed to every tick, the readings are: in the first 9 ticks the second set of carriers has not yet formed Laws, the weights and the bearing organization are both unchanged, and neither is signed; from tick 10 on, the second set of carriers form Laws one after another and continue to sediment, the proportions of the weights change at every step, and only RateDyn is signed; under tick-by-tick evaluation no step signs RateBearingStructDyn. This can be reproduced by rerunning the same path with certify of Appendix A, setting eval\_every of this task to 1. That is another reading under another evaluation protocol and does not affect the certificate above; it also shows that the hit of G\_Bear depends on the frozen evaluation protocol; this dependence is declared in advance, not selected after the fact.

Implementation-copy contrast

The same initial state, the same 18-step path, but π\_role frozen as Left2 ↦ Left1, Right2 ↦ Right1, NewRoute2 ↦ NewRoute1. Then the carrier organization changes while the projected family of formal hyperedges is unchanged, and this path does not hit G\_Bear (Appendix B, bear\_on\_implementation\_copies). So "one more set of carriers" cannot itself serve as evidence of hitting; whether it hits depends on the frozen role identity, not on the number of carriers. This contrast shows only that this path does not constitute a certificate; it does not constitute a negative verdict "G\_Bear is unreachable".

## Section Eleven　Negative Verdicts, ⊥ and the Discipline of Stochastic Paths

11.1 A negative verdict must cover all permitted paths

Example: with the empty substrate as initial state and a permitted set of idle ticks only (M = {idle tick}, U = O = ∅), target G\_Prob. The actual route of an idle tick is empty, so there is no sedimentation at all on any path: the rep of every path stays 0, no path forms a Law, V\_P stays empty, D = 0, and Probability stays 0. This argument holds for every H and every permitted path, so SuppReach = 0. This 0 is obtained by a proof of invariance; the run of 50 idle ticks in Appendix B is only a demonstration, not a proof.

11.2 Failure in finitely many attempts can only be recorded ⊥

Example: with the initial state of G\_Bind as initial state, execute only the first 8 steps of its path; there is no hit (Appendix B, bounded\_failure\_is\_bot). This cannot be signed 0: a longer permitted path does hit (Section Nine).

11.3 An unpermitted operation invalidates the path

Example: under the permitted set of G\_Prob, take another path: after Left1 and Right1 alternate for 6 rounds, step 13 walks NewRoute1 via G0 (this path is not the 8-step certificate of Section Seven). The certificate reports at that step "not within the permitted set", the path is invalidated and does not serve as evidence of hitting; the certificate records at the same time that the anchor did not change and that 12 running steps were actually executed (Appendix B, unadmitted\_route\_rejected). Admission failures and anchor changes are recorded separately. This corresponds to the breach method of the Canon Chapter, "the given path contains an unpermitted operation".

### 11.4 Stochastic paths

The reference implementation is deterministic. If a future running specification carries a stochastic kernel, "ran several times without arriving" can likewise only be recorded ⊥; "arriving with positive probability" and "arriving with probability one" must be reported separately and do not replace SuppReach here.

## Section Thirteen　Breach Methods

13.1 The two classes of breach prescribed by the Canon Chapter

Class A: proving that, under the declared initial state, permitted set, target and frozen evaluation protocol Γ\_reach, no permitted path can hit the target.

Class B: pointing out that the certificate path given is illegal, that is, contains an unpermitted operation.

### 13.2 The concrete forms of Class B here

The path contains a route, mode or operation not in the permitted set; the path changes, midway, the candidate anchor, π\_role, run, branch or protocol; the hit evaluation step has SamePDynBind ≠ 1, or its reading depends on coverage that is ⊥; the target is obtained by directly writing readings, rewriting logs or changing the evaluation protocol after the fact. If any of these holds, that certificate is invalid, and the corresponding SuppReach = 1 falls back to ⊥ until another legal certificate is given.

### 13.3 Local breaches of additional claims

Finding a permitted hitting path shorter than 8, 4, 12: breaches only the corresponding proposition of the shortest number of steps, not SuppReach = 1.

Reading "one more set of implementation copies" as a hit of G\_Bear: breaches that one determination of G\_Bear and its application of the role projection, not automatically the other eight reachabilities.

Signing a failure of finitely many attempts as 0, or writing "there exists a path" as "all paths" or "with probability one": breaches the corresponding statement of strength.

    Evaluation points are fixed by the frozen rule Γ_reach (eval_every): a_Γ(0)=0 and
    a_Γ(k)=k·eval_every.  The path end is NOT promoted to an evaluation point."""

        if not admissible(act,task["Adm"]): admission_fail.append((j,act)); break
        apply(F,act); executed=j
        if anchor(F)!=a0: anchor_change.append(j); break

    legal=not admission_fail and not anchor_change

        else:

    return {"task":task["name"],"theta":theta,"X0_t":t_start,"eval_every":eval_every,
