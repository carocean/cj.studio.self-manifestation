# The Mathematical Form of Field Induction

## Section 1  Purpose

### 1.1  Structural Sources

The first five papers of this Group Form give the necessary structure of five kinds of objects:

　　Field Induction  Ind(ι) ⇒ ∃T, g \[Org₀ ∧ GoalRep ∧ Target ∧ ΔΦ\_W ≠ 0 ∧ Eff ∧ Bear ∧ GoalCond\], with modes of action branching by implementation layer and route (a label; it confers no event qualification);  
　　Host adjustment  Retune(κ) ⇒ six duty groups ∧ Rewrite ∧ Bear\_R;  
　　Tuning  Tune(κ) ⇒ six duty groups ∧ Gate ∧ Bear\_G;  
　　Tendency raising  Prime(κ) ⇒ Pot ∧ MechC ∧ Init ∧ Acq, κ = (F, H, M, R, o, t*, T*);  
　　Field construction  Make(κ) ⇒ Ev ∧ D1 ∧ 𝒫 ≠ ∅ ∧ S ∧ MechC; Make\_C(κ) adds ∧ D2, and the comparisons of GoalResp start from the same H, M, entry state, input, environment, random source and W.

Readings shared by the five papers: bearing requires only participation, and one bearing moment within W suffices; “the part depended on” is taken as structural dependence (Appendix Definition 1 of *The General Form of Field Induction*: with one and the same rest r fixed, there exist legitimate c₁, c₂ for which the readings differ); acts are classified by the actual implementation layer and route on the induced field, and the identity and location of the actor play no part in the classification; mechanism labels confer no event qualification.

These structures are given in natural language. On a concrete declared host—who wrote what and when, by which route, whether a write actually changed a value, which variables took part in determining which subsequent writes—where and when each of them holds calls for a formal system that can be computed item by item.

### 1.2  The Object of Formalization

Write S\_Ind for the necessary structure of the five papers. This Form establishes a formal system for it:

　　S\_Ind ⟼ M\_Ind

The Form kind is Mathematical Form: a principal form, first edition. Entry conditions: S\_Ind has been established by the five papers in the necessary direction, and the terminology of its components is stable. The Field-Concretization Qualification, the mechanism and the host attribution of the induced field are inherited from the five papers and are not conferred by any formal value of M\_Ind.

### 1.3  Declared Scope

Finite executable domain: variables, events, phases and goal families are finite; values are rationals; every event function is totally defined on its value domain and terminates in one step. For the relational layer (real values, continuous time, infinite goal families, general functions) only definitions and three-valued evaluation rules are given; no general solution procedure over it is established.  
Expressible actions: writing rational values into θ, m, r and ext variables, and installing uninstalled θ variables through acquisition or direct write. Disconnection—making an installed connection uninstalled—has no corresponding transition in this syntax; histories containing disconnection are outside the declared domain.

## Section 2  Core Theses

Thesis 1 (Evaluation on witnesses)  The bearing-type relations of the five papers—Bear, Bear\_R, Bear\_G, GoalCond, D1, D2—are all relations on mechanism witnesses, and the trajectory does not suffice to decide them: two writes can give the same end state, an overwritten write leaves no trace at the end point, and a variable that is only read in, without affecting the value written, does not bear. M\_Ind records, for each atomic event, its route, its reads and writes, its actual change, the versions it reads in, its per-output dependence and its sources, and evaluates three-valuedly on these witnesses.

Thesis 2 (Classification by route)  Modes of action are formalized by actual implementation layer and route: direct write writes the physical layer through an act port; gating writes the dynamic layer through an act port; sedimentation writes the physical layer by the field's own rules; acquisition turns the physical layer from uninstalled into the acquired organization; input writes only ordinary running state. Who the actor is, and whether it is inside or outside the field, do not enter the classification.

Thesis 3 (Read-back has a direction)  Formal value 1 is read back, under the bridging conditions listed in Section 7, as the corresponding necessary item holding; formal value 0 excludes the upstream structure only on items with proved negative coverage, and elsewhere only the formal value is reported; ⊥ is undetermined; domain invalidity is listed separately. That the formal values of all the necessary items are 1 is not read as the corresponding event having been established.

## Section 3  Basic Objects and the Definition Sequence

Definitions are given in order of dependence; each ends with a note of the structural item it corresponds to (the correspondence table is in Section 7).

Definition 3.1 (Declared model)  𝔐 = (V, λ, Dom, Φ, deg\_Φ, Supp, Ports, F\_M, X\_ext, fid).  
\- V is the set of state variables; λ(v) ∈ {θ, m, r, ext}: θ is the physical layer (installed connections and their weights, signs and rule parameters); m is the dynamic layer (patency and degree of permeability on existing connections, present only when the model declares a dynamic layer); r is ordinary running state (input, activation, membrane potential, traces, refractory periods, firing records and so on); ext comprises the variables outside the induced field (the states of the actor, the goal bearer and other out-of-boundary processes).  
\- Uninstalled: a connection or Structural Position not installed on the host does not appear in the state; installed with value 0 is a different state.  
\- Dom(v): a finite value domain, or a predicate value domain together with a finite ordered substitution sequence. Initial values and all written values must lie in the value domain.  
\- Φ: the reading, which declares its reading level L and input class 𝓘; it reads only the θ and m layers, is a mathematical read-out, injects no signal into the field, and is not an event; it is defined on partial states and counts only installed pathways. deg\_Φ(v) is an upper bound on the polynomial degree of Φ in v, a nonnegative integer or undeclared.  
\- Supp: the connection on which each dynamic-layer variable lies; when a dynamic-layer variable appears in the state, its connection must be installed.  
\- Ports: the act ports, giving the variable sets writable by Rw, Gt, Acq and In respectively.  
\- F\_M: the component table of the field's own basic rules; each component registers its kind (Sed or Run) and its writable variable set; a rule that cannot be split uniquely is registered as a joint component.  
\- X\_ext: the component table of out-of-boundary processes; each component is of kind Run, and its write set contains only ext variables; it does not belong to F\_M.  
\- fid: the registered identifier of the induced field, fixed at construction.  
If any item fails its declaration, the model is domain-invalid. \[Corresponds to: the induced field and the declaration of its working domain\]

Definition 3.2 (Events and contract)  An event is ε = (id, kind, reads, writes, fn, deg, part, src, ctrl, asp).  
\- kind ∈ {In, Run, Sed, Rw, Gt, Acq}. src specifies the route: Run and Sed must cite a component of the same kind in F\_M or X\_ext, and their write set may not exceed that component; Rw, Gt, Acq and In must pass through the port of the same name, and their write set may not exceed that port.  
\- part marks the act (or the field itself, or the environment); ctrl is the declared set of mode-of-determination variables (Definition 3.6(d)) and may be omitted; asp is an aspect name and may be omitted. An event that declares an aspect name and acts through a port by direct write, gating or acquisition is called a procedural event; input events and field-rule events are not procedural events even if they carry an aspect name. Within one run, the aspect names of procedural events are pairwise distinct.  
\- id is taken from the event-identifier domain 𝔈 and is unique within a run; writes may contain one or more variables, and an event whose writes contain only one is a single-output event; deg is the polynomial degree of fn in each read-in variable and may be omitted. fn is evaluated on the pre-write state.  
\- Contract: the read-in variables are declared and have values; the actual output keys of fn equal writes; the layer written is compatible with kind (In and Run write r or ext; Sed, Rw and Acq write θ; Gt writes m); written values lie in the value domain; a gating write lands on an installed connection; the ctrl variables are declared and have values.  
If any of these fails, that run is domain-invalid. \[Corresponds to: modes of action reported separately by implementation layer and route\]

Definition 3.3 (Phases and snapshots)  Each atomic event occupies one subphase, and phases increase strictly in lexicographic order; the entry is (0, 0). The snapshot σ\_τ of subphase τ is the full set of state values after the event at τ has written; the entry snapshot is the initial values; for the same moment the source map anc\_τ and the version-source map vanc\_τ are also recorded. An indivisible joint process is represented by one joint event, which has no intermediate states. \[Corresponds to: W and the moments within it\]

Definition 3.4 (Actual change)  If the value that event ε writes to variable x differs from the pre-write value (or x was uninstalled before the write), ε is said to actually change x. The formal images Rewrite^f and Gate^f of direct-write and gating events are taken as “there exists an Rw or Gt event, respectively, with an actual change.” \[Corresponds to: the change left by the act\]

Definition 3.5 (Three-valued dependence)  For a function f, an argument assignment args and a variable v: replace v with a substitute value from its value domain, keeping the other variables at their values in args; if f changes, dep(f, args, v) = 1; if the test is complete and f does not change, dep = 0; otherwise dep = ⊥. The test is complete in exactly two cases: v has a finite value domain that has been fully enumerated; or f declares a degree upper bound d in v, and d legitimate substitute values, pairwise distinct and all different from the current value, have been tested (the substitute values are first normalized as exact rationals, those that are not legitimate or equal the current value are removed, duplicates are removed preserving order, and only then are they counted).  
This is local dependence with the actual background fixed. dep = 1 gives a difference on one actual background, and the actual background is one of the legitimate backgrounds, so it witnesses structural dependence in the sense of Appendix Definition 1; dep = 0 says only that there is no difference on this background, and is not a proof that structural dependence is absent. \[Corresponds to: “the part depended on” taken as structural dependence—one-directional\]

Definition 3.6 (Sources)  The source domain 𝔖 = 𝔈 ⊎ 𝔄 is the disjoint union of the event-identifier domain and the holding-anchor identifier domain; sources are matched by type and identical identifier. Each variable x carries a source map anc(x): a finite subset of 𝔖 → {determined, undetermined}. All outputs of an event compute their sources from the pre-write state and the pre-write source snapshot, and are committed together once computed.  
(a) When event ε actually changes x, anc(x) = {ε: determined}, merged with: anc(u) for every read-in variable u with dep = 1; the entries of anc(u), merged as “undetermined,” for every u with dep = ⊥; nothing from those with dep = 0. Determined takes precedence over undetermined.  
(b) If a Sed, Rw, Gt or Acq event writes x with a value equal to its pre-write value: no source is generated, and anc(x) is unchanged.  
(c) If an In or Run event writes x with a value equal to its pre-write value, but redetermined by its present read-ins: the event is not recorded as a source, and anc(x) is reassigned to the result of merging from the read-in variables per (a) (not including the event itself). Events that write the goal variable (by whatever route) are excepted and follow (b).  
(d) When an event declares ctrl, the pre-write sources of each variable in ctrl are merged, in their existing status, into the sources of every actually changed output of the event: determined ones stay determined, undetermined ones stay undetermined. A control edge guarantees only that the variable took part in determining the occurrence, position or timing of the event; it does not upgrade the status of its upstream sources. The ctrl declaration belongs to the trusted premises (5.2).  
A multi-output event computes the sources of each output separately per (a)–(d); the sources of one output are not merged into another output. \[Corresponds to: the act taking part through an actual route; bearing chain\]

Definition 3.7 (Versions and version sources)  Each actual change produces a version ν = (x, n, ε): the nth actual change of x, generated by ε. The version sources are vanc(ν) = {ν: determined}, merged with the pre-write current version sources of the read-in variables with dep = 1 (those with dep = ⊥ merged as undetermined) and with the pre-write current version sources of the ctrl variables (in their existing status). A reassignment per 3.6(c) produces no new version; instead it registers a source-refresh node (x, n\~, ε), whose sources are obtained from the read-ins in the same way; thereafter whatever reads in x reads this refresh node. Holding anchors also appear as one class of elements in version sources.  
Direct-source edges: for a version or refresh node k = (x, ·, ε), its direct sources are the pre-write current nodes of the read-in variables of ε on which x depends with value 1 (value-write edges) and the pre-write current nodes of the ctrl variables of ε (control edges). \[Corresponds to: bearing paths on the same output\]

Definition 3.8 (Goal declaration, registration and goal sources)  
(a) Target-pointing registry 𝒯: TargetDecl(g) = (induced-field identifier φ′, relation template).  
(b) Goal declaration GoalDecl = (role Xg, goal variable g, induced field φ).  
(c) Run entry: a run with GoalDecl requires that 𝒯 contain TargetDecl(g) and that φ = φ′ = fid; if the registration is missing or any of these is unequal, the run is domain-invalid.  
(d) Goal sources are registered in two kinds. The holding anchor at entry: Xg already holds g at entry, with identifier in 𝔄; its role and variable must agree with GoalDecl, and g must be in the ext layer and available at entry, otherwise the run is domain-invalid; a holding anchor is not an event and not a physical change. Goal-write events within the window: src is the goal-setting component, part is Xg, the write set is exactly {g}, and g is actually changed; the identifier is in 𝔈. A legitimate run may have no goal-source registration.  
\[Corresponds to: GoalRep(Xg, g), Target(g, F)\]

Definition 3.9 (Formal predicates of Field Induction, host adjustment and tuning)  Fix an act a (marked by part), a time window W and a subset K of event kinds. The events of a within W are the events whose part is a and whose phase lies in W; the bearing moment τ ranges over the snapshot phases within W; events before W do not count as events of a within W, and appear in source maps only as sources (upstream sources).  
P1 Org₀^f: the set of θ installed at the entry of W is nonempty.  
P2 GoalRep^f: GoalDecl is valid and a goal source has been registered; ⊥ if none is registered. Target^f(g) (a registry query, not a run): ⊥ if 𝒯 has no TargetDecl(g); 1 if it has one and its induced field is fid; 0 if it has one and the field differs.  
P3 ΔΦ^f\_W: Φ(σ\_{W end}) − Φ(σ\_{W entry}), a quantity; what enters the three-valued table is the predicate ΔΦ^f\_W ≠ 0.  
P4 Eff^f(a): some event of a within W actually changes the θ, m or r layer of the induced field. The landing points taken are those where a value changes.  
P5 BearAt\_K(a, τ): 1 if there exists v with dep(Φ, σ\_τ, v) = 1 such that anc\_τ(v) contains, marked determined, an event of a within W with kind ∈ K and an actual change; 0 if for every v at τ either dep = 0 or anc\_τ(v) contains no such event; otherwise ⊥. Bear\_K(a; W) is the strong Kleene disjunction over τ ∈ W. Bear^f, Bear\_R^f and Bear\_G^f take K to be all kinds, {Rw} and {Gt} respectively.  
P6 GoalCond^f\_Π(a): Π = (kind set, layer set) is the declared event filter, by default all kinds × {θ, m, r}. ⊥ if no goal source has been registered; 1 if some event of a within W whose kind is in Π actually changes a variable whose layer is in Π and, after the write, the sources of that variable contain a registered goal source as determined; ⊥ if they contain one only as undetermined; 0 otherwise. The modes of determination covered are the value-write chain and the occurrence, position and timing declared per 3.6(d).  
P7 Rewrite^f(a), Gate^f(a): a has, within W, an Rw or Gt event, respectively, with an actual change. For the expressible direct-write landing points see 1.3; disconnection is not among them.  
\[Corresponds to: the six duty groups of *The General Form of Field Induction*; Rewrite and Bear\_R of *The General Form of Host Adjustment*; Gate and Bear\_G of *The General Form of Tuning*\]

Definition 3.10 (Formal predicates of tendency raising)  
P8 T*^f(o, t*): among the variables actually changed by Acq events of o at or before t*, those whose current version at t* was generated by an Acq event of o, together with their values at t\*.  
Preservation interval: an interval \[t₁, t₀\] is valid if and only if t₁ ≤ t₀ and t₁, t₀ are both snapshot phases.  
P9 Pot^f(T, t₀): (a) T is installed at t₀; (b) T is nonempty; 0 if (a) or (b) fails. (c) 1 if dep(Φ, σ\_{t₀}, v) = 1 for some v ∈ T; 0 if every test is complete and gives 0; otherwise ⊥.  
P10 MechC^f(𝔐, 𝒲): 𝒲 is the declared finite set of witness protocols, each protocol a sequence of legitimate events. The route of every event in a protocol must belong to the declared mechanism routes (F\_M components, declared out-of-boundary components, or declared port routes) or be an explicitly permitted input; a protocol containing other routes does not serve as a witness. ⊥ if the mechanism is undeclared; 0 if the declaration is exhaustive and no route writes θ; if in some admissible protocol there is a version ν of a θ variable x such that  
　(1) the version sources of ν contain, as determined, a version generated by an input event (legitimate triggering, actual trace left);  
　(2) some later event reads in x while the current node of x is still ν, and one and the same output of that event both depends on x with value 1 and has an actual change (can be read in, actually depended on);  
　(3) some later event actually changes some θ variable, its new version sources contain ν as determined, and there is a path of direct-source edges from ν to that version (historical dynamics; it may be a multi-segment chain through out-of-boundary records and write-back);  
then 1, the witness being ν, the read-in event and its output, the historical version and that path; otherwise ⊥.  
P11 Init^f(o, t*, t₀, R): t* ≤ t₀, t₀ is the starting point of the declared run R, and T*^f(o, t*) is nonempty, installed at t₀, and takes its values at t\*.  
P12 Acq^f(o, t*, t₀): \[t*, t₀\] is valid; T*^f(o, t*) is nonempty; at every snapshot phase within the interval, every variable of T\* keeps its value at t*. Only variables belonging to T* are checked.  
\[Corresponds to: Pot, MechC, Init, Acq of *The General Form of Tendency Raising*\]

Definition 3.11 (Formal predicates of field construction)  τ is the declared target structure and Crit\_τ its criterion (defined on partial states, with its read set required to be installed).  
P13 S^f(W): at each snapshot phase, 1 for that phase if some θ or m variable has dependence 1 for Φ; 0 if every test is complete and gives 0; otherwise ⊥. Across phases, take the strong Kleene disjunction.  
Formation: if τ does not hold at the snapshot at the start of W and holds for the first time at some later phase within W, τ is said to form within W, and that phase is the first-formation phase; formation outside W does not count.  
P14 FormBear^f(𝒫, τ; W) (D1): at the first-formation phase, (i) 1 if some variable of the criterion read set has dependence 1 for Crit\_τ and its version sources contain, as determined, a version generated by some event of 𝒫 (separable); (ii) 1 if two criterion variables, taking legitimate substitute values together, flip Crit\_τ and the version sources of both contain versions of 𝒫 as determined (pairwise joint); ⊥ if something is undetermined or coverage is insufficient; 0 otherwise. When τ has not formed within W, FormBear^f takes the value “not applicable”: the value domain of P14 is {1, 0, ⊥, not applicable}.  
Comparison object: for the declared τ and the finite goal family 𝔊\_τ, every goal branch runs from the same entry state; the comparison object is the immutable ordered tuple (the complete witness record of each branch, 𝔊\_τ, the read set and complete evaluation specification of Crit\_τ, W, the formation verdict of each branch within W, the admission verdict). The complete witness record comprises the model, all event records, the states and sources at each snapshot phase, the version-source and current-node tables, and the goal-source registrations; the complete evaluation specification of the criterion comprises every parameter the criterion reads (thresholds and the like). Each component of the comparison object takes its value at admission: W is a pair of phases, and the environment, the random source and the common run specification of the branches are their content values; thereafter they are unrelated to any mutable object in the run. Admission: within one branch the aspect names of procedural events are pairwise distinct; the trajectory of every branch covers W; the common run specifications of the branches are identical—the model, all non-procedural events (field-rule events and input events: phase, kind, route, read set, output keys, the complete specification and degree of the rule), the values of all actual exogenous inputs within W (whether or not the input events carry aspect names), the entry state (except the goal variable), the environment, the random source and W. Only procedural events are left out of the common run specification. If any of these fails, the admission is invalid.  
P15 GoalResp^f: domain-invalid if the admission is invalid; otherwise 1 if τ forms within W under the main goal and does not form within W under some alternative goal, and 0 otherwise. A comparison without a bound criterion read set serves only for evaluating P15 and is not a comparison object of P16.  
Aspect differences: the aspect differences of procedural events are registered per output as (aspect, output variable) → kind of difference. For strength, only the outputs whose values differ between the main branch and the alternative branch are registered; for a different operation or timing, all outputs of that aspect are registered; if the aspect does not occur in the alternative branch, all outputs of that aspect in the main branch are registered; if it does not occur in the main branch, or the write sets differ so that they cannot be aligned, the aspect is recorded as undetermined. A\_G is the set of all registered items; its goal versions are the versions of these outputs in the main branch generated by the events of that aspect. What is compared is the aspects the procedure issues, not whether there is an actual change.  
P16 GoalForm^f (D2): evaluated only on a comparison object whose admission is valid and whose criterion read set is bound; the evidence used—including the read set and evaluation specification of the criterion—is taken only from that object; evaluation first checks that the branch set and each bound item are the same as at admission, and then evaluates the criterion; the value domain is as for P14; it is evaluated per P14 on the same W, with the goal versions of A\_G in place of the versions of 𝒫; it is ⊥ when there is an undetermined aspect and the result is 0. When the admission is valid and GoalResp^f = 0, D2 is still evaluated by definition.  
P17 Ev^f(𝒫; W): evaluated only for the events of 𝒫 whose phase lies within W; events outside W take “not applicable,” do not enter the aggregate, and appear only through their sources, as upstream sources. For each event within W, only the coverage items applicable to its class are evaluated—tendency-raising event: actual change, and preservation of what is acquired over \[event phase, t₀\] (with the same interval and per-phase criterion as P12); direct-write event: actual change, Rewrite, single-event bearing, goal determination; gating event: actual change, Gate, single-event bearing, goal determination. Single-event bearing takes that event alone as the act and is evaluated per P5, with both events and snapshots windowed; goal determination means that the version sources contain, as determined, a holding anchor or a version generated by a registered goal-write event. The output is a per-event three-valued table of applicable items, a list of uncovered duties, and an aggregate value: the strong Kleene conjunction of all applicable items of all events within W; when there is no 𝒫 event within W, the aggregate is “not applicable.” Uncovered duties do not enter the aggregate. 𝒫 ≠ ∅ and the nonemptiness of 𝒯 and 𝔊 are declared separately.  
\[Corresponds to: Ev, D1, 𝒫 ≠ ∅, S, GoalResp, D2 of *The General Form of Field Construction by Self-Manifestation-Field Induction*\]

Relations and properties (domain and direction declared item by item):  
\- ≺\_𝕋 (between subphases): a strict total order.  
\- Pred(ν, ν′) (between versions of the same variable): ν is the immediate predecessor version of ν′, ν coming first. As ν′ ↦ ν it is a function on non-initial versions; irreflexive; in general not transitive. Its transitive closure ≺\_ver: a strict partial order, total on each variable, with versions of different variables incomparable.  
\- Src(e, e′): e′ has an actual change, and e belongs to the sources, after the write, of some actually changed output of e′; reflexive on events with an actual change. The quantifier ranges across outputs.  
\- AncEv⁺(e, e′) :⇔ Src(e, e′) ∧ e ≠ e′ (between events): irreflexive; time-precedent; antisymmetric. Transitivity is guaranteed when the intermediate event is single-output (Proposition 5.3); with multiple outputs it is not guaranteed in general, though individual chains may happen to be transitive.  
\- VAnc(ν, ν′) :⇔ ν ≠ ν′ ∧ ν belongs to the version sources of ν′ at its generation (between versions): irreflexive, time-precedent, antisymmetric, transitive (Theorem 5.4). Bearing paths across events are represented by VAnc and direct-source edges, and connect the same output.  
\- HoldAnc (holding anchor × variable): a heterogeneous relation; holding anchors do not enter the relations between events or between versions.  
\- Same part (between events): an equivalence relation.  
\- Alt\_τ(G, G′) :⇔ G, G′ ∈ 𝔊\_τ ∧ G ≠ G′: the domain is the declared finite goal family; irreflexive, symmetric, not transitive.  
\- Identity of common run specification (between branches): an equivalence relation, compared by content, not by name.  
\- dep: three-valued, not an order relation. “⊆” between gating support and installed connections: a partial order.

## Section 4  Equations

M\_Ind sets up no separate dynamical equation: the dynamics are given by the F\_M components of the declared model, acts by port events, and out-of-boundary processes by X\_ext. The run equations are event-by-event updates:

(State)  σ\_τ = σ\_{τ⁻}\[x ↦ fn(σ\_{τ⁻}\|reads)(x) : x ∈ writes\], where τ⁻ is the preceding snapshot phase.  
(Actual change)  Δ\_ε = {x ∈ writes : fn(σ\_{τ⁻}\|reads)(x) ≠ σ\_{τ⁻}(x) or x was uninstalled before the write}.  
(Sources)  For x ∈ Δ\_ε: anc\_τ(x) = {ε: determined} ⊔ ⨆\_{u: dep=1} anc\_{τ⁻}(u) ⊔ ⨆\_{u: dep=⊥} ↓anc\_{τ⁻}(u) ⊔ ⨆\_{c ∈ ctrl} anc\_{τ⁻}(c); ⊔ is union with determined taking precedence, and ↓ lowers every entry to undetermined. For x under 3.6(c), drop the entry {ε: determined}; for x under 3.6(b), anc\_τ(x) = anc\_{τ⁻}(x).  
(Version sources)  The same formula as (Sources), with vanc and current nodes in place of anc and variables.  
(Reading)  Φ(σ\_τ) counts only installed pathways.  
(Bearing)  BearAt of P5, and the strong Kleene disjunction over the whole window.

## Section 5  Running and Solving

### 5.1  Running

Event by event: check the contract (Definition 3.2) and the entry (Definition 3.8(c)), execute, compute the sources and version sources of each output (from the pre-write snapshot), commit them together, and keep the snapshot. GoalResp^f and GoalForm^f make finitely many complete runs over the goal family, checking admission first.

5.2  The Finite Executable Domain and the Trusted Premises

For the finite executable domain see 1.3. Trusted premises: every function is totally defined on its value domain; the declared degree upper bounds are true; the declarations of kind, src and ctrl agree with the actual execution route and mode of determination; every actual landing point of the act on the induced field has been registered as an event and is expressible in this syntax (declaration completeness); identity of the complete specifications of rules and criteria is decidable, and criteria and rules read only the parameters listed in their specifications. These premises are not certified by solving; when they are false, the evaluation verdicts lose their validity with them.

### 5.3  Three Kinds of Result

(1) Domain-invalid: the model, a declaration, an event or a comparison fails the contracts and admission of Definitions 3.1, 3.2, 3.8 and 3.11.  
(2) Undetermined ⊥ (within a legitimate run): an incomplete dependence test; no goal source registered in the run (GoalCond^f, GoalRep^f); a mechanism witness not obtained on the declared protocols; an aspect that cannot be aligned.  
(2′) Not applicable: P14 and P16 take this value when τ has not formed within W; in P17, events outside W, and the aggregate when there is no event within W, take this value. It is neither 0 nor undetermined.  
(3) Certified 1 or 0. The registry query Target^f is not a run and has its own three values.

Theorem 5.1 (Finite termination)  Within the finite executable domain, for any declared model, finite event sequence and finite goal family, running, the updates of sources and version sources, and the evaluation of P1–P17 terminate in finitely many steps and return, for each predicate, one element of its value domain (for P14 and P16, {1, 0, ⊥, not applicable}; for P17, the per-item table and an aggregate value in {1, 0, ⊥, not applicable}; for the rest, {1, 0, ⊥}) or domain invalidity.  
Proof: The number of events is finite; the execution of each event, its contract check and the dependence test for each read-in variable involve only finitely many substitute values; merging sources and version sources is a finite set operation; P10 enumerates over finitely many protocols; the pairwise probes of P14 and P16 enumerate over finite value domains or finite substitution sequences; GoalResp^f and GoalForm^f make one finite run for each member of the finite goal family. ∎

Theorem 5.2 (Reassignment changes only sources)  The reassignment of 3.6(c) and the refresh nodes of 3.7 change no state value and no reading trajectory.  
Proof: (c) acts only when the written value equals the pre-write value, and changes only anc(x) and the current node of x; event functions do not read sources, and Φ reads only the θ and m layers; by induction on phases, the state values and Φ of every snapshot are unchanged. ∎  
P5, P6, P10, P14 and P16 depend on sources, and where (c) takes effect they may take values different from those under a rule without reassignment; M\_Ind evaluates uniformly by Definitions 3.6 and 3.7.

Proposition 5.3 (Event transitivity under the single-output condition)  If e′ is a single-output event, then AncEv⁺(e, e′) ∧ AncEv⁺(e′, e″) ⇒ AncEv⁺(e, e″); when both antecedents are determined, so is the consequent.  
Proof: Let the sole output of e′ be x′, with sources A′ after the write, and e ∈ A′. As a source, e′ is generated only in A′; thereafter every source set is either kept or obtained by merging in, whole, the source sets of some read-in variables (for dep = 1 each entry keeps its status, for dep = ⊥ entries are lowered to undetermined, for ctrl they keep their status). Induction on phases gives two invariants: every source set containing e′ contains all elements of A′; in every source set in which e′ is determined, the elements determined in A′ are also determined. The result follows from AncEv⁺(e′, e″) and the two invariants. ∎  
If e′ has several outputs, e′ is generated separately in the source set of each output, the remaining elements of these sets may differ, and the event projection need not be transitive (7.3 has an example).

Theorem 5.4 (Version relations)  VAnc is a strict partial order.  
Proof: Each version ν appears as a new element only once, in the version-source set at its generation; thereafter version-source sets are only kept or obtained by whole-set merging. Hence the two invariants of Proposition 5.3 hold for every version without the single-output condition: every version-source set containing ν contains all elements of vanc(ν). Transitivity follows; irreflexivity holds by definition; time precedence holds because version sources contain only versions already generated; antisymmetry follows from time precedence. ∎

Proposition 5.5 (Closure of the comparison object)  The evaluation of P16 reads only evidence within the comparison object, including the read set and complete evaluation specification of the criterion; the comparison object is immutable. When P16 is evaluated, the same content representation is recomputed for the existing branches, W, environment and random source, and compared item by item with the values in the comparison object. Hence the common run specification and formation verdicts that held at admission and the evidence read at evaluation are one and the same body of evidence: a comparison whose admission is invalid, or a tuple in which any branch evidence, W, environment, random source, criterion read set or criterion specification differs from its value at admission, is not a comparison object, and P16 is domain-invalid on it.  
Proof: By the definition of the comparison object (Definition 3.11), its components are fixed when it is formed; the definition of P16 refers only to these components. ∎

## Section 6  Coupling

6.1  With the first five papers  The formal predicates of M\_Ind are formal images, on the declared host, of the structural items of the five papers; for correspondence, direction and strength see Section 7.

6.2  With *The Mathematical Form of the Field* v2.7  Correspondence in use: the component of the θ layer that carries the depth of sedimentation (the weight) is a finite-layer representation of the Sedimentation-Degree δ, that is, of where sedimentation is recorded. Correspondences not established: which objects of *The Mathematical Form of the Field* the connection set, the signs and the rule parameters in the θ layer each correspond to; the threshold, the convergence condition κ and Familiar Routes have no formal image in M\_Ind. 6.3  With *The Mathematical Form of Field Concretization* v1.0  Both take the route of “keeping mechanism witnesses, evaluating three-valuedly.” P10 is a rule-level witness of the declared mechanism on finite protocols; the duty evaluation of *The Mathematical Form of Field Concretization* is carried out on actual windows; neither substitutes for the other.

6.4  With *The Mathematical Form of Computation* v1.0  Running in the r layer corresponds to what that Form calls actual events, and must carry bridging condition B1 (formal events correspond to node writes and driving pathways in the actual run); write-back in the θ layer corresponds to a transformation of the host level.

6.5  With *The Mathematical Form of Error-Driven Host Adjustment* v1.0  The witness language the two Forms share—declared model, event contract, phases, actual change, three-valued dependence, source maps and bearing evaluation—is, in that Form, a restricted form of M\_Ind; its computation graph (its Definition 3.2) and training quantities (its Definition 3.9) are structures proper to its implementation class 𝒞\_EDR. Its component table of out-of-boundary processes is X\_ext of Definition 3.1; its source reassignment for same-value writes by In and Run is as stipulated in Definition 3.6(c) (evaluated on the pre-write source snapshot, with no reassignment for writes to the goal variable); its source domain is likewise the disjoint union of event identifiers and holding-anchor identifiers. Its GoalCond^f is the reading of P6\_Π with Π = {Rw} × {θ}: it checks only the direct-write events of act a that actually change θ. The two are equivalent only on this projection; if the same part also has events that change the r layer, P6 under the default Π may differ from that Form's GoalCond^f.

### 7.2  Read-Back Rules

Rule 1  Formal value 1 is read back affirmatively under the bridging conditions. Formal value 0 means that the formal predicate is false within the declared domain; it excludes the upstream structural item only on items marked “excludable” in the table above and under the conditions listed there; if that item is a necessary item of some event class and the working-domain premises are met, the corresponding candidate can be excluded. For any other 0, only the formal value is reported. ⊥ is undetermined. Domain invalidity is listed separately and is not a formal value.  
Rule 2  That the formal values of all the necessary items are 1 is not read as the corresponding Field Induction, host adjustment, tuning, tendency raising or field construction having been established.  
Rule 3  Numerical changes in criteria and readings are not read as the content the goal points to already having qualification; GoalCond and D2 are read out only from sources and version sources.  
Rule 4  When the variables in the criterion read set have finite value domains, full enumeration without a flip gives 0; when they have predicate value domains, a criterion containing inequalities declares no degree, and single-variable tests give only 1 or ⊥. Variables not in the criterion read set have declared degree 0. The substitute-value family must cover the range in which the flip lies, and pairwise probes are taken on the same family of legitimate substitute values.

### 7.3  Read-Back Examples

The readings in all the following examples are mathematical read-outs.

Field Induction (host H₀): θ = {w, th, e}, Φ = w − th; the field's own rule (deepening) is w ← w + e·s·w, where s is the input; at entry w = 1, th = 0, e = 1/10, and Xg holds g = 2 at entry.  
\- Goal-driven direct write w := g + 1: ΔΦ = 2; Org₀^f, Eff^f, Bear^f, GoalCond^f, Rewrite^f and Bear\_R^f are all 1.  
\- Fixed-schedule direct write w := 19/10 (not reading g): Bear^f = 1, GoalCond^f = 0, formal value only. If the time at which the same write occurs is determined by g and ctrl = {g} is declared, GoalCond^f = 1.  
\- Cancellation: a writes w := w + 1, b writes w := w − 1: Bear^f(a) = 1, and ΔΦ^f\_W ≠ 0 is 0.  
\- Environmental inflow without a goal declaration (three inputs s = 1 with deepening): Bear^f(env) = 1, GoalCond^f(env) = ⊥.  
\- Window: after the goal-driven direct write there is one more input with deepening. Over the whole run Bear\_R^f = 1; when W is taken to be the two phases after the direct write, the direct write is not an event of a within W, Bear\_R^f = 0 and GoalCond^f = 0, and the direct write serves only as an upstream source. Evaluating Ev^f with that direct write as the event of 𝒫: over the whole run, single-event bearing and the aggregate are both 1; on the same truncated window, the event takes “not applicable,” and the aggregate is “not applicable.”  
\- Control edge: a field-rule event reads g and writes q, its dependence test on g is incomplete, and the holding anchor is undetermined in the sources of q; the direct write w := 3 declares ctrl = {q}. The holding anchor remains undetermined in the sources of w, and GoalCond^f = ⊥.  
\- Event filter: act a first rewrites an r-layer variable according to g by a Run event, then makes a same-value direct write. Under the default Π, GoalCond^f = 1; with Π = {Rw} × {θ} it is 0.

A 0 on a local background: Φ = w1·w2 + w3, entry (1, 0, 0); a writes w1 := 2, b writes w3 := 1. Throughout the window w2 = 0, and Bear\_R^f(a) = 0, while on the legitimate background w2 = 1, w3 = 0, Φ varies with w1. This 0 reports only the formal value.

Same-value output: an out-of-boundary event, from the pre-write state, simultaneously writes s := 1 (an actual change) and rec := s (pre-write s = 0, equal to the pre-write value 0 of rec). The sources of rec are reassigned, from the pre-write snapshot, to the empty set, which does not include this event; the source of s is this event.

Multi-output event: e1 directly writes w := 2; e2, through an out-of-boundary component, simultaneously writes s := 1 and rec := w + 1; e3 reads s and writes s := 1 − s. AncEv⁺(e1, e2) (via rec) and AncEv⁺(e2, e3) (via s), yet e1 is not among the sources of e3. The version relations (w, 1, e1) → (rec, 1, e2) and (s, 1, e2) → (s, 2, e3) are each transitive and do not chain together.

Mechanism condition (host H₀ and its variants; in the protocols the input s enters through the input port):  
\- Deepening mechanism, protocol “input, deepening, input, deepening”: MechC^f = 1, with path (w, 1) —value-write→ (w, 2).  
\- Mechanism declaration exhaustive and no route writes θ (empty mechanism or read-only mechanism): 0. Mechanism undeclared: ⊥.  
\- Identity write-back w ← w: no actual change, ⊥. Write-back w := 1 + s, which reads in w without depending on w: ⊥.  
\- Two declared routes: tr writes w := 1 + s; use reads w and writes th := w/2: 1, path (w, 1) —value-write→ (th, 1). If use is not declared in the mechanism, protocols containing use do not serve as witnesses: ⊥.  
\- Out-of-boundary retention and later write-back: tr writes w := 1 + s; an out-of-boundary record component writes rec := w; after the next input s = 0, tr writes w := 1; then w := rec is written back through the direct-write port. 1, path (w, 1) —value-write→ (rec, 1) —value-write→ (w, 3). If the record component writes the same value when rec already equals w (while also rewriting another variable), the path passes through the source-refresh node of rec.  
\- One output of an out-of-boundary event has the same value and depends on w, while its other, changed output does not depend on w: (2) fails, ⊥.

Tendency raising (host Q): two branches x→h1→y and x→h2→y, Φ = a1·b1 + σ·a2·b2, counting only installed pathways.  
\- Uninstalled at entry (every connection's key absent): Org₀^f = 0, Pot^f(∅) = 0. Every connection installed at entry with value 0: Org₀^f = 1; (c) of Pot^f is a local 0 on that background, formal value only.  
\- Cancellation: σ = −1, uninstalled at entry, o acquires all 1s: Φ = 0; Pot^f, Init^f, Acq^f and S^f are all 1. The reading is zero, yet the organization bears a tendency.  
\- Endpoint restored: o acquires b2 = 2, another act changes it to 3 and then back to 2: Acq^f(o) = 0 (some phase in the interval does not keep the value); in Ev^f the preservation item of that acquisition event is also 0.  
\- t\* earlier than the acquisition: Acq^f = 0, Init^f = 0. A write partway through the run (not an acquisition event): Init^f = 0, Acq^f = 0. A process o′ that writes only an out-of-boundary log: Acq^f(o′) = 0. A θ variable not belonging to T\* changes within the interval: Acq^f is still 1.

Tuning (host G₀, flux reading Φ = w1a·w1b·m1 + w2a·w2b·m2): at entry m1 = 1, m2 = 0, w2b = 2, and Xg holds g = 1; a, according to g, writes m1 := 1 − g and m2 := g: Φ goes from 1 to 2; Gate^f, Bear\_G^f and GoalCond^f are all 1.

Field construction (host Z): connections x→h1, h1→y, x→h2, h2→y, x→h3, h3→z; the field's own rule, when the input s = 1 arrives, adds to each of the two connections of every pathway 1/10 of that pathway's flux s·w\_a·w\_b; the criterion of the target structure τ\_h2 is P2 ≥ 2 and P2 \> P1 (P1, P2 being the weight products of the two branches); W runs from the entry to beat 6, with one input and one write-back per beat.  
\- Controllable field construction: uninstalled at entry; one tendency raising acquires all 1s, followed by one direct write that, according to the goal, writes the non-target branch: under G\_h2, w(x→h1) := 3/10; under G\_h1, w(x→h2) := 3/10. GoalResp^f = 1; A\_G is the strength of the two direct-write aspects (in the G\_h2 branch, writing w(x→h2) := 1 equals the acquired value and generates no version); D2^f = 1, with first formation at beat 4, separable via w(x→h1); D1^f = 1.  
\- Path separation: the field pre-exists, and the process changes only the z-side w(h3→z): D1^f = 0.  
\- Chance growth: pseudorandom tendency raising, with a procedure that does not read the goal: GoalResp^f = 0, A\_G = ∅, D1^f = 1.  
\- Ev: in the controllable field construction example, the tendency-raising event o(x→h2) makes an actual change and is preserved, and the applicable items of the direct write b(x→h1) (actual change, Rewrite, single-event bearing, goal determination) are all 1; in the G\_h2 branch b(x→h2) writes the same value, so its actual change is 0, and hence the aggregate over the three events is 0.  
\- Compound tendency raising that changes only a marker: one acquisition event writes all six connections, and only w(x→h3) takes 1/3 or 9/10 according to the goal. GoalResp^f = 0; A\_G contains only the single output w(x→h3) of that event; D2^f = 0. Treating the whole event as varying with the goal, and taking as ground that any output of the event bears the formation, would yield an affirmative verdict; per-output registration separates the goal-determined output from the outputs that bear the formation.  
\- Timing only: the same direct write lies at different phases in the two branches, and A\_G registers it as a “timing” aspect.  
\- Joint aspects: the criterion is a ≥ 1 or b ≥ 1, and both aspects take 1 or 0 according to the goal. No single-variable substitution flips the criterion; the pairwise legitimate substitution (0, 0) flips it, and D2^f = 1 (joint). If the criterion is changed to a ≥ 0 and b ≥ 0, no pairwise substitution within the value domain {0, 1} flips it, and D1^f = 0.  
\- Differing common run specification (the entry state, a port, the rule of a component of the same name, or one of the actual inputs within W differs, the last whether or not the input event carries an aspect name): the admission is invalid, and GoalResp^f and D2^f are domain-invalid. Two procedural events with the same name in one branch: the admission is invalid. When W contains only the single entry point, τ does not form within W, GoalResp^f = 0, and D1^f and D2^f are not applicable.  
\- Criterion binding: after the joint example has been admitted with read set {a, b}, evaluating D2 with read set {a} instead, or changing a threshold the criterion reads after admission: neither is that comparison object, and D2^f is domain-invalid. If, after admission, the environment content of the alternative branch changes, or the starting point of W changes: likewise domain-invalid; for the valid comparison in which the environment contents of the two branches are the same at admission, D2^f = 1.

Spiking network: θ = {w} (the pre→post synapse), m = {m} (the patency of that synapse), r contains the postsynaptic membrane potential u, the postsynaptic firing z, the refractory counter, the pre- and postsynaptic traces, the presynaptic firing, the direct-drive input to the postsynaptic neuron, and the interneuron's input, membrane potential and firing; ext = {g}. Φ = m·w.

Under the presynaptic firing sequence 1, 1, 0, 1, postsynaptic firing is 1, 0, 0, 1 (beat 2 falls in the refractory period).
