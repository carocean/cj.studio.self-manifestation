# 律身份配对区分式

第一节

目的、式种与唯一任务

### 1.1 唯一任务

对两份已分别取得正式 Law 资格的 occurrence：Law 侧声明的配对与物理 root 的配对，是否其实只是同一个跨端关系？

所证不是二者的定义写法不同，而是：存在一个合法的观测，在其上两者的产出必然不同。

　　OccPair\_LS ≠ OccPair\_B

并直接得

　　OccPair\_LS ⇏ OccPair\_B

两个候选都是配对规则。它们说的是「按此规则，这两份 occurrence 被配成一对」，不是「这两份 occurrence 是同一个 Law」。哪一种配对与身份有关、有何种关系，不在本篇之内。

### 1.2 式种

区分式，附式，独立成篇。

按法篇第一第四编第十二章，区分式的用途为证明存在观测能把两个候选结构或假设分开；其进入条件为两个候选的定义已分别闭合、两个候选的前向映射都已给出；其标准写法为候选对申报、区分观测构造、区分有效性证明、区分定理、接口；其完成条件为区分观测显式且有效性证明完成；其击穿方式为展示在该观测下两个候选产出相同的情形；其禁止写法为以统计倾向差冒充区分、观测无法执行、候选定义不闭合。

区分式不追问对象的最小结构，只问有无一个观测能把两者分开。因此不用一般式的递推写法。

第二节

上游输入与工作域

### 2.1 上游承继

《律组式》与《律判定式》（封版）——两端的正式 Law 资格。Law = 1 必须沿封版体系的正式判定取得，不得因结构规格看起来像律便把端点当作 Law。

《律动力运行基底构造式》（封版）——三样：真实运行的 Law occurrence 与其正式证书；形式 witness 与物理路径之间的 PathMap 桥，该桥是桥接规则而非动力变量；以及同一规格可有多个合法实例，不同能力无须全部压在同一状态。

《律数理式》（封版）——形式解集 𝒮( F, L, I )。

### 2.2 两端

　　λ\_a = ( F\_a, t\_a, L\_a, I\_a )  
　　λ\_b = ( F\_b, t\_b, L\_b, I\_b )

### 2.3 进入条件

　　Law\_{F\_a, t\_a}( L\_a, I\_a ) = 1  
　　Law\_{F\_b, t\_b}( L\_b, I\_b ) = 1

对象的进入条件只此两项。不要求 F\_a = F\_b；不要求两端位于同一条轨迹；不要求二者之间存在历史承接；不要求来源关系；更不要求二者同一。

某份观测能否进入有效域 𝒴\_pair^adm，另必须满足两个候选各自的可读条件，见 6.2。二者分属两层，不相混。

### 2.4 两端可互无往来

两端可以来自不同的运行实例。正因不要求二者有任何联系，第六节的区分观测才可以取两个独立实例。

复制、迁移、替换、分裂、合并、恢复、Law = 0 之后重现、来源与身份边界各问，都在本篇之外，不得借其答。

第三节

候选一：Law 侧声明配对

### 3.1 协议

冻结

　　Γ\_LS^can

它只读取已经存在的 Law 侧正式声明，并排除物理实例的命名空间。

### 3.2 canonical 声明签名

　　DeclSig^can( λ ) ≔ Canon\_{Γ\_LS}( L, I, Rel(L), … )

由该 occurrence 的正式候选声明之中，经 Γ\_LS^can 事前指定的 Law 侧内容组成，例如 Rel(L)、Ante、Anchor、Type、Read、Cov、Trig、I 各项之中所选的。

所读者是形式的 Law 侧声明结构，不是该 occurrence 在场中实现出来的沉积结构。二者必须分清：上游本以候选 L 与 Rel(L) 为预给对象，而运行实例另经正式解与场状态的资格链，证明该候选在当前场中真正成律。同一份声明与两实例中的实际结构相同，不是一回事。

以上各项不是身份的本体组成，只是该配对规则所读取的字段。列出它们不主张它们构成身份。

### 3.3 定义

　　OccPair\_LS^can( λ\_a, λ\_b ) =  
　　　　1　　若 DeclSig^can( λ\_a ) ≡\_{Γ\_LS} DeclSig^can( λ\_b )  
　　　　0　　若二者可比较而 canonical 对应失败  
　　　　⊥　　若所需的 Law 侧声明不可读或不可比较

### 3.4 它不是身份

　　OccPair\_LS = 1　⇏　SameLaw = 1

它只表示：按冻结的声明配对规则，这两份 Law occurrence 被配成一对。

### 3.5 协议取最窄读法

Γ\_LS^can 只比对其事前指定的字段，不裁定字段之外的变化是否仍可对应。

此限定是有意的：放宽即碰身份边界，而那是别篇的事。

第四节

候选二：物理 root 配对

### 4.1 形式见证不是物理承载

此处最要紧的一条纪律：

　　R　≠　physical bearer

R 是形式见证，物理承载是场中的实际路径。二者必须分层。第七篇即以 PathMap 作为 Law 侧承载到实际物理路径的桥，并注明该桥不是新增的动力变量。

### 4.2 canonical 见证选取

正式解为解集

　　𝒮( F, L, I )

其中可有不止一份合法见证。若以「存在一对见证使其足迹同 root」定取值为一，则取值为零必须排尽一切合法见证对；而本篇的区分观测只取一对足迹，两者不合。

因此不以存在量词立此候选，而事前冻结一个选择函数：

　　Sel\_B^can( F, L, I ) ∈ 𝒮( F, L, I ) ∪ { ⊥ }

其要求有四：规则事前冻结；不读取 SameLaw；同一输入唯一返回一份 R；无可选见证时返回 ⊥。

选择规则不得留作后定。本篇 v1.0 将其作为 Γ\_B^can 的组成部分一并事前冻结：

　　Γ\_B^can = ( 选择规则, root 比对规则 )

所取的是

　　Sel\_B^can = min\_lex( 𝒮\_listed )

即按冻结的字典序取 𝒮\_listed 的第一项。

　　𝒮\_listed ⊆ 𝒮( F, L, I )

为该 occurrence 在实现中所列出的合法见证，其列出方式由 Γ\_B^can 一并冻结。二者的区别必须说准：𝒮 是理论的解集，未必可逐一列举；𝒮\_listed 是实现中确已列出的。选择函数取自后者。

若 𝒮\_listed 为空，则 Sel\_B^can 返回 ⊥，该侧读出随之为 ⊥。

不得写作「换一个满足上列四条的规则，结论不变」。该句未经证明，且有反例可虞：若某 occurrence 有两份合法见证 R\_1 与 R\_2，而二者经 PathMap 落到不同的 root，则换一个选择规则即可改变 OccPair\_B 的取值。

因此必须说准：其它满足上述准入条件的选择规则，可以形成别的合法物理 root 配对候选；而本篇不证明不同选择规则所生成的各候选彼此等价，也不证明本篇的区分结论对任意选择规则都保持。

选择规则既已冻结进 Γ\_B^can，此候选才是闭合。

此法不要求 \|𝒮\| = 1。解集可以有多份见证，而配对只看冻结规则所选的那一份。

记

　　R\_B^can( λ ) ≔ Sel\_B^can( F, L, I )  
　　Foot\_B^can( λ ) ≔ PathMap( L, R\_B^can( λ ) )

### 4.3 root 配对

冻结最窄的物理配对协议 Γ\_B^can，只比对 root：

其中 Root( q ) 为足迹 q 所在运行实例的 root 标识，由 Γ\_B^can 所冻结的 namespace 读出；它只标识实例，不载 Law 侧内容，也不载跨态历史。

　　RootPair\_B^can( q\_a, q\_b ) = 1　⟺　Root( q\_a ) = Root( q\_b )

可读而不等的为 0；不可读者为 ⊥。

此处不涉 carrier lineage。替换、迁移、复制、分裂、合并的跨态追踪都不在此协议之内——引入它即把跨态 tracking 的问题带回，而区分观测并不需要它。

### 4.4 定义

　　OccPair\_B^can( λ\_a, λ\_b ) =  
　　　　1　　若 Root( Foot\_B^can( λ\_a ) ) = Root( Foot\_B^can( λ\_b ) )  
　　　　0　　若二者都可读而 root 不同  
　　　　⊥　　若任一 canonical 见证或其足迹不可读

三值都由冻结规则单值确定，无存在量词。

### 4.5 它也不是身份

　　OccPair\_B = 1　⇏　SameLaw = 1

第五节

两个候选各自闭合

### 5.1 各自所读

OccPair\_LS 只读取 Law 侧的正式声明。

OccPair\_B 只读取 Γ\_B^can 所冻结的选择函数取得的见证，经 PathMap 落到的足迹与其实例 root。

### 5.2 各自单值

二者对同一份观测包各返回一个确定的值。

Law 侧：DeclSig^can 由 Γ\_LS^can 所指定的字段逐项读得，其比对结果单值。

物理侧：其单值性系于 4.2 所冻结的选择函数。若不冻结而取存在量词，则要取值为一就必须遍历见证对，要取值为零就必须排尽见证对，该侧便非单值的读出。Sel\_B^can 对同一输入唯一返回一份见证，故足迹与 root 随之唯一，取值单值。

### 5.3 各自不调用者

二者都不调用 SameLaw，不调用 LawSource，不调用 NoFork，也不调用对方的输出。

### 5.4 故候选闭合

由 5.1 至 5.3，二者作为两个候选的前向映射已分别闭合：各有其所读、各自单值、各不循环。区分式的进入条件满足。

### 5.5 二者之间无本体层级

不得写「结构层对应的是 Law 本身，而 bearer 只是实现」一类话。该句会给两者排出本体高下，而本篇未证、也不拟证任何此类结论。

二者是两个不同读取面上的配对规则，如此而已。

第六节

公共观测包与区分观测

### 6.1 公共观测包

　　Y\_pair = ( λ\_a, λ\_b, Cert\_a, Cert\_b,  
　　　　　　　DeclSig\_a, DeclSig\_b,  
　　　　　　　R\_a^can, R\_b^can, Foot\_a^can, Foot\_b^can, Root\_a, Root\_b,  
　　　　　　　Γ\_LS^can, Γ\_B^can )

其中 Cert\_a、Cert\_b 为正式的 Law 资格证书。

### 6.2 有效工作域

　　𝒴\_pair^adm

要求：Cert\_a = PASS，Cert\_b = PASS；结构字段可按 Γ\_LS 求值；物理足迹可按 Γ\_B 求值。

于是有两个前向映射

　　Y\_pair ⟼ OccPair\_LS( Y\_pair )  
　　Y\_pair ⟼ OccPair\_B( Y\_pair )

### 6.3 区分观测的构造

取同一个封版运行规格所许的两个独立合法实例

　　ι\_A, ι\_B ∈ Inst( Spec\_LDB )

此构造方式上游已有制度：Inst( Spec\_LDB ) 是该固定规格在共同规则下所产生的合法实例与轨迹的集合，而同一规格中的不同合法实例本就可分别作见证，不要求一切能力出现在同一状态之上。

两实例采用相同的冻结 Law 侧候选声明

　　L\*，　I\*

以及同一 canonical Law 侧形式 schema。

于 ι\_A 之中形成 occurrence λ\_A，并按正式判定得 Law( λ\_A ) = 1。  
于 ι\_B 之中形成 occurrence λ\_B，并按正式判定得 Law( λ\_B ) = 1。

两端的资格由上游的正式体系取得，本篇以其证书为接口前件输入，不重跑上游的判定动力。附录 A 的参考实现中，该前件以 law\_pass = True 表示。

### 6.4 该观测在有效域之内

两端的证书都是 PASS；两端的 Law 侧声明都可按 Γ\_LS 求值——二者用同一 schema；两端的 canonical 见证都可由 Sel\_B^can 取得，其足迹与 root 都可按 Γ\_B 求值——二者各在自己的实例之中有实际的承载路径。

因此

　　Y\* ∈ 𝒴\_pair^adm

### 6.5 观测可执行

此观测不依赖任何不可观测的量。所需的是：两份正式 Law 证书；两份按冻结 schema 求得的声明签名；两份由冻结选择函数取得的见证，及其经 PathMap 落得的足迹与 root。

各项都可在申报的实现环境中查得。

第七节

区分有效性

### 7.1 Law 侧的产出

二者用同一份冻结的 canonical 声明，其经 Γ\_LS^can 指定的字段逐项同值：

　　DeclSig^can( λ\_A ) = DeclSig^can( λ\_B )

按 3.3

　　OccPair\_LS^can( λ\_A, λ\_B ) = 1

此处所得的是声明层的相同，非两实例中实现结构的相同，见 3.2。

### 7.2 物理 root 的产出

由 Sel\_B^can 于两端各取一份 canonical 见证，经 PathMap 落得足迹 q\_A 与 q\_B。

二者属两个独立的运行实例，其 root namespace 不同：

　　Root( q\_A ) ≠ Root( q\_B )

按 4.3 与 4.4，二者都可读而 root 不同，故

　　OccPair\_B^can( λ\_A, λ\_B ) = 0

此取值由冻结的选择函数单值确定，不涉「是否存在某一对见证使其同 root」的问题——4.2 已不以存在量词立此候选。

### 7.3 区分

　　Y\* ：　( OccPair\_LS, OccPair\_B ) = ( 1, 0 )

在此观测之上，两个候选的产出必然不同。

### 7.4 反检查：root 的差异确实决定物理侧的产出

上节所得的 OccPair\_B = 0，必须证其非硬编码的常量，而确由 root 的差异触发。

保持三者不变：Law 侧声明不变；canonical 见证不变；PathMap schema 不变。只把第二端的实例 root 改为与第一端相同，则

　　OccPair\_B^can　0 → 1

这是该侧读出的敏感性对照：保持其余输入不变，只把 root 的相等由假改为真，其输出随之由 0 变为 1。因此该读出的取值确由所声明的 root 关系决定，而非硬编码的常量。

其强度必须说准。此对照不替代 H\_PAIR2 与 K-PAIR4 对 root namespace 真实性的外部核验：两个 root 是否只是标签不同而实际共享同一物理 root 或同一状态对象，必须由实现环境自身查证，不能靠把标签手动改成相同来验。前者验的是读出对输入的敏感，后者验的是输入本身是否属实，二者不同层。

## 附录 A 的参考实现以断言执行此对照。断言不过即中止，故附录 B 末行的 PASS 本身即其通过的证明。

### 7.5 此非统计倾向的差

法篇所禁止的情形之一，是以统计倾向差冒充区分。此处不涉倾向：两个产出各由其冻结协议在同一观测包上确定地求得，一为 1，一为 0，不是某种分布上的偏移。

第八节

区分定理

定理一　候选闭合

在 Γ\_LS^can 与 Γ\_B^can 之下，

　　OccPair\_LS^can，　OccPair\_B^can

都是 𝒴\_pair^adm → { 1, 0, ⊥ } 的非循环前向映射。

证明分两项。

单值。由 3.3，Law 侧的取值由 Γ\_LS^can 所指定的字段逐项读得。由 4.2 与 4.4，物理侧的见证由冻结的 Sel\_B^can 唯一取得，其足迹与 root 随之唯一，取值也唯一。因此二者对同一观测包各返回一个确定的值，见 5.2。

非循环。由 5.3，二者都不调用 SameLaw、LawSource、NoFork 或对方的输出。

二项既立，二者都是所称的映射。∎

定理二　显式区分观测

存在合法的

　　Y\* ∈ 𝒴\_pair^adm

使

　　OccPair\_LS( Y\* ) = 1，　OccPair\_B( Y\* ) = 0

证明。6.3 给出该观测的构造，6.4 核其在有效域之内，6.5 核其可执行；7.1 与 7.2 分别给出两侧产出的求值。∎

定理三　配对区分

　　OccPair\_LS ≠ OccPair\_B

且

　　OccPair\_LS ⇏ OccPair\_B

证明。由定理一，二者都是定义于 𝒴\_pair^adm 之上的映射，其定义域相同。由定理二，Y\* ∈ 𝒴\_pair^adm，且

　　OccPair\_LS( Y\* ) = 1　≠　0 = OccPair\_B( Y\* )

两个定义域相同的映射，若其共同定义域中有一点取值不同，则二者不是同一个映射。Y\* 即该点，故

　　OccPair\_LS ≠ OccPair\_B

又该点在共同定义域之内而前者取 1、后者取 0，这就是前者成立而后者不成立之一例，故

　　OccPair\_LS ⇏ OccPair\_B

反向的非蕴含不由此得，理由见 10.2。∎

到此停止。

第九节

三种偷换的封锁

三种误读都不由上节的定理推出，而都可能被误作其结论。逐条封死。

### 9.1 不得由独立推出不同律

不得写：两实例独立，所以是两条不同的 Law。

本构造之中的「独立」只承担一件事：Root\_A ≠ Root\_B。这是观测中的事实。

OccPair\_B = 0 不是它另行承担的一件，而是据 4.3 与 4.4 对该事实的求值——事实归事实，读出归读出，中间隔着冻结的协议。

而二者都不承担 SameLaw = 0。判两份 occurrence 本体上不同，必须有一个身份判据，此处没有。

### 9.2 不得由同一声明推出同一律

不得写：两实例使用同一份声明，所以是同一条 Law。

同一份 canonical 声明只承担一件事：DeclSig^can( λ\_A ) = DeclSig^can( λ\_B )。此也为观测中的事实，而 OccPair\_LS = 1 是据 3.3 对它的求值。

二者都不承担 SameLaw = 1，也不承担两实例中的实现结构相同。

### 9.3 不得据跨实例能力排出本体高下

不得写：声明配对能跨实例而 root 配对不能，所以声明比承载更接近身份。

定理三只证 OccPair\_LS ≠ OccPair\_B。它不含任何优劣结论。

这一条尤其要留意。所取观测的形状恰是 Law 侧为 1 而 root 侧为 0，这样读极易生出「声明更根本」的印象——而那只是观测的形状，不是所证的内容。若反向的分离世界日后被构造出来，其形状将是 root 侧为 1 而 Law 侧为 0，届时同样不能据此推出「承载更根本」。

第十节

最小性

### 10.1 所指

区分式不证构成项的不可删。此处的最小性是区分观测的最小性：为证 OccPair\_LS ≠ OccPair\_B，只需一个使二者产出不同的 Y\*。

因此 ( 1, 0 ) 一份证书已足。不需要反向世界 ( 0, 1 )，不需要穷尽候选空间，不需要加入来源或历史连续分量，不需要构造身份本体。

### 10.2 不得为求完整而补作反向世界

补上它即把一件未证的事写成封版前件。反向的非蕴含

　　OccPair\_B ⇏ OccPair\_LS

不在本篇所证之列；其所需的分离世界记为 G\_Pair-RevSep，留作未来构造。

### 10.3 未证之列

SameLaw 的定义与判定；两候选与 SameLaw 之间的任何一向蕴含；上述反向非蕴含。

复制、迁移、替换、分裂、合并、恢复、Law = 0 之后重现、来源与身份边界，都不在本篇，见 2.4。

第十一节

条件项与状态

### 11.1 H 组

只两项。

H\_PAIR1　端点资格前件。两端的 Law 证书依赖上游封版的律判定体系，该体系的前件继续传导。其前件若被撤销，本篇的进入条件失效。

H\_PAIR2　物理实例 root 可审查前件。物理实例的 root 具有唯一且可审查的 namespace。这是实现接口，非身份本体的 H。

### 11.2 不得入 H 的项

结构身份、来源、无分叉、复制与迁移，都与上节的定理无关，不入 H。写入它即看似对身份本体有所承诺。

### 11.3 理论状态与实例化状态分记

法篇要求区分「式本身的成立状态」「实例化状态」与「外部连接状态」。实例化未完成不得冒充理论击穿，也不得反过来把理论证明写成已经运行。因此分记：

　　理论状态　　　　　　　　　Conditional，条件化于 H\_PAIR1 与 H\_PAIR2  
　　配对层实例化状态　　　　　 PASS  
　　上游 fldb\_v1\_12.py 端到端复跑　未执行

配对层的最小可执行参考实现已实际运行，得

　　OccPair\_LS^can = 1，　OccPair\_B^can = 0，　separated = True

并通过 7.4 的同 root 反检查。全文与运行记录见附录 A 与附录 B。

该实例化的范围必须说准。它是配对层的最小 harness：以 law\_pass = True 表示上游正式体系已经签出的 Law 端点资格，以 formal\_witnesses = ( "R1", ) 与 path\_map( "L1", "R1" ) 表示上游已成立的正式见证及 PathMap 接口。

它不重新证明 R1 ∈ 𝒮，也不重新生成 PathMap，只测本篇新增的两个配对读出及其区分。

它不是对封版 fldb\_v1\_12.py 原始源文件的重新端到端执行。第七篇的既有封版运行状态按上游既有记录承继，不由此实例化重新验证。

### 11.4 Status

　　Conditional

条件化于 H\_PAIR1 与 H\_PAIR2。

### 11.5 不主张

两个候选的双向非蕴含；任一候选与身份的任何关系；两候选之间的本体高下；候选空间的穷尽。

第十二节

击穿

按法篇第四编第十二章，区分式的击穿方式为展示在该观测下两个候选产出相同的情形。据此列一条核心击穿与三条辅助击穿。

K-PAIR1　核心击穿。

　　OccPair\_LS( Y\* ) = OccPair\_B( Y\* )

若在所申报的同一合法观测 Y\* 之上二者输出相同，则核心的区分证书失败，定理二与定理三随之失败。

K-PAIR2　候选未独立闭合。有二形态。其一，展示任一候选实际调用了 SameLaw、LawSource 或对方的输出，则非循环一项失败。其二，展示任一候选对同一观测包可返回不止一个值——如物理侧的见证未经冻结规则唯一取得——则单值一项失败。二者有一，候选的定义即不闭合，本篇失去区分式的进入条件，定理一失败。

K-PAIR3　端点未取得资格。展示任一端点并未按正式判定取得 Law = 1。则 Y\* ∉ 𝒴\_pair^adm，不能作区分观测。

K-PAIR4　root 的差异只是标签。展示所谓的两个独立 carrier root 只是标签不同，而实际共享同一物理 root 或同一状态对象。则 OccPair\_B( Y\* ) = 0 没有证书，观测失效。

四条都可由审稿人直接执行核验：K-PAIR1 查两侧求值；K-PAIR2 查两候选的定义所调用者，并查其对同一观测包的返回是否唯一；K-PAIR3 查两份证书；K-PAIR4 查两实例的 root。

不是击穿的：反向世界未构造——反向非蕴含不在所证之列，见 10.2；两候选与身份的关系未定——不在所问之内；上游 fldb\_v1\_12.py 未作端到端复跑——11.3 已分记，配对层 harness 的 PASS 不以该复跑为完成条件。

第十三节

接口

### 13.1 向上

《律组式》与《律判定式》（封版）——两端的 Law 资格，按其正式判定程序承继。

《律动力运行基底构造式》（封版）——Law occurrence 与其证书、PathMap 桥、同一规格多实例的制度。本篇不修改 Spec\_LDB。

《律数理式》（封版）——形式解集 𝒮，4.2 的合法见证取自其中。

理篇各篇——身份与空间承载不可直接混同，这是上游的既有约束。

　　理篇并未证明第八节的定理。它只提供这一层分层的上游约束，而第六节的 Y\* 才承担区分的证明。

### 13.2 向下

定理三——下游可用作「Law 侧声明配对与物理 root 配对不可互相冒充」的依据。引用时必须连同 11.1 的两项前件与 11.4 的 Conditional 状态一并承继。

方向的限定——所证只到 OccPair\_LS ⇏ OccPair\_B。下游不得据此推出反向的非蕴含。

　　　　G\_Pair-RevSep

　　此前研发中曾拟的 Spec\_ITB 不废，降级为该缺口的未来构造工具，不入封版条件。

无本体高下——第九节三条随结论一并传导。下游不得据本篇推出任一配对更接近身份。

无身份结论——下游不得据此取得任何关于两份 occurrence 是否同一的断言。

### 13.3 篇际边界

~~~python
# law_identity_pairing_test_v0_1.py
# Minimal executable interface test for
# On Self-Manifestation · Law Dynamics Group Form 8
#
# NOTE:
# - This tests only the new Chapter-8 pairing layer.
# - It does NOT re-run the sealed fldb_v1_12.py model.
# - law_pass=True represents an already-signed upstream Law endpoint certificate.

from dataclasses import dataclass
from typing import Any, Dict, Tuple, Optional

@dataclass(frozen=True)
class LawOccurrence:
    instance_root: str
    field_id: str
    time_id: int
    law_id: str
    domain: Tuple[str, ...]
    law_pass: bool
    formal_witnesses: Tuple[str, ...]
    law_side_spec: Tuple[Any, ...]

def sel_b_can(occ: LawOccurrence) -> Optional[str]:
    if not occ.formal_witnesses:
        return None
    return sorted(occ.formal_witnesses)[0]

def path_map(law_id: str, carrier_id: str) -> Dict[str, Any]:
    table = {
        ("L1", "R1"): {
            "branch": "A",
            "depth_nodes": ("m1", "c"),
            "carrier_edges": (("a1", "m1"), ("m1", "c")),
        }
    }
    return table[(law_id, carrier_id)]

def foot_b_can(occ: LawOccurrence) -> Optional[Dict[str, Any]]:
    r = sel_b_can(occ)
    if r is None:
        return None
    pm = path_map(occ.law_id, r)
    return {
        "root": occ.instance_root,
        "carrier_edges": pm["carrier_edges"],
        "branch": pm["branch"],
    }

def occ_pair_ls_can(a: LawOccurrence, b: LawOccurrence):
    if not (a.law_pass and b.law_pass):
        return None
    if a.law_side_spec is None or b.law_side_spec is None:
        return None
    return 1 if a.law_side_spec == b.law_side_spec else 0

def occ_pair_b_can(a: LawOccurrence, b: LawOccurrence):
    if not (a.law_pass and b.law_pass):
        return None
    fa, fb = foot_b_can(a), foot_b_can(b)
    if fa is None or fb is None:
        return None
    return 1 if fa["root"] == fb["root"] else 0

L1_SPEC = (
    ("law_id", "L1"),
    ("I", ("a1",)),
    ("ante", "a1"),
    ("anchor", ("m1", "c")),
    ("read", "c"),
    ("carrier_schema", (("a1", "m1"), ("m1", "c"))),
)

lam_A = LawOccurrence(
    instance_root="instance_A/root", field_id="F_A", time_id=100,
    law_id="L1", domain=("a1",), law_pass=True,
    formal_witnesses=("R1",), law_side_spec=L1_SPEC,
)
lam_B = LawOccurrence(
    instance_root="instance_B/root", field_id="F_B", time_id=100,
    law_id="L1", domain=("a1",), law_pass=True,
    formal_witnesses=("R1",), law_side_spec=L1_SPEC,
)

ls_val = occ_pair_ls_can(lam_A, lam_B)
b_val = occ_pair_b_can(lam_A, lam_B)

print("[Chapter8 interface-level executable test]")
print("OccPair_LS_can =", ls_val)
print("OccPair_B_can  =", b_val)
print("separated      =", (ls_val, b_val) == (1, 0))

assert ls_val == 1
assert b_val == 0
assert ls_val != b_val

lam_B_same_root = LawOccurrence(
    instance_root="instance_A/root", field_id="F_B2", time_id=100,
    law_id="L1", domain=("a1",), law_pass=True,
    formal_witnesses=("R1",), law_side_spec=L1_SPEC,
)
assert occ_pair_b_can(lam_A, lam_B_same_root) == 1
print("[PAIRING_TEST_TOTAL] PASS")
~~~
