自显论 · 律篇 · 律动力组式第十一 v1.0

# 律交互数理式

第一节

目的

### 1.1 这套系统要解决什么问题

一次 LawDyn 事件发生了，场上不止一条律。要判断其中某一条律是否真的参与了这次事件的发生。

难处在于：两条律共用一段介质时，承担者之间总有种种物理影响——发热改了阻抗，占用挤了带宽，电流在共地上引起偏移。这些影响确实到达了目标，却与那条律的职责无关。凭「两条律都在场」或「目标当时变了」来判断，会把这类影响一并算作律际交互。

本系统给出一套可执行的判法：输入一个已经跑完的场与轨迹、两份 Law-role 引用、一次目标事件，输出

　　Read^M\_INT ∈ { 1, 0, ⊥ }

1 表示确有一份属于 source 律职责的贡献，实际进入了这次事件的生成；0 表示读全了而没有；⊥ 表示材料不足以判定——这一值不写作 0，读不出与读得而不成立是两回事。

判法分两步查、一步绑：第一步查这份贡献是不是那条律的职责所发，第二步查它是不是真进了这次事件的生成机制，再查两步认的是不是同一份贡献、同一段执行、同一次事件。

### 1.2 所形式化的结构

上面三步不是本篇新立的，它们是第十篇所证的必要结构：

　　S\_IntBear = LawInteractionBear

出自该篇第十二节的总式。本篇为它建立形式系统：

　　S\_IntBear ⟼ M\_IntBear

式种为数理式，主式，独立成篇，首版。按法篇第一第三编第二章定种。其进入条件是结构已由证明主式成立、各分量已有稳定术语；S\_IntBear 由第十篇封版证成，两层与绑定纪律都有稳定术语。

### 1.3 边界

第十篇证明的是 LawInteraction ⇒ LawInteractionBear，它的逆向尚未证明，归第十二《律交互必然式》。

因此本系统的结构输入只取 Bear，回读也止于

　　Read^M\_INT = 1　⇒　LawInteractionBear = 1

1 不推出这一次交互成立，只推出交互所必需的那套结构成立。

所依据的轨迹 η 是已经发生的合法实际执行轨迹，因此一切枚举都限制在已发生的实际支撑之内，见 5.3。本系统不问「有没有可能发生」，只问「已经发生的这一次里，那条律有没有进去」。

第二节

核心论题

### 2.1 中心内容

本系统要精确表达的中心内容是一条判准：把属于律的职责贡献，与承担者的物理影响分开；并使每一次判定都落在同一份贡献、同一段执行、同一次事件之上。

分开之所系，在于贡献是否沿职责一路可读：自源点的形式见证，到这一次职责的 realization，到所申报的职责，再到该律的关系组织。凡是沿此链读通的属职责贡献，凡是只沿承担者的物理通路走的不属。

落在同一处之所系，在于四重同证：第一层三项必须依同一份记录；第二层的事件事实与机制进入必须属同一次事件；路径上必须是同一条血脉自源点一路传至目标；两层所认的必须投回同一个对象层的键。四者缺一，各处都真而合起来不成一次交互——那是拼证。

凡是读不出的返第三值，不冒充读得而不成立。

### 2.2 自上游承继而来的结构

第十篇已经冻结下列内容，本系统按其原样承继。

　　LawInteractionBear　≡　Bind\_INT( SourceLawContribution, TargetDynGeneration )

展开为

　　LawInteractionBear = 1  
　　　⟺　SourceLawContribution = 1 ∧ TargetDynGeneration = 1 ∧ SameInteractionBind = 1

其中有两个本体层，一条绑定纪律。

对象层的绑定键是

　　β\_int = ( L\_S, r\_s, c\_S, Z\_ST, L\_T, e\_T )

### 2.3 工作输入

　　𝕀\_INT = ( F, η, L\_S, I\_S, L\_T, I\_T, e\_T, Γ\_INT )

各项的含义：

　　F　　　沉积场  
　　η　　　已经发生的合法实际执行轨迹  
　　L\_S, I\_S　source-role 的 Law 及其适用域  
　　L\_T, I\_T　target-role 的 Law 及其适用域  
　　e\_T　　目标的 LawDyn 事件  
　　Γ\_INT　事先冻结的交互读出协议

### 2.4 冻结协议

　　Γ\_INT = ( Γ\_src, Γ\_path, Γ\_event, Γ\_bind, Γ\_read )

各项分管的内容：

　　Γ\_src　　怎样读取 source 一侧的贡献 occurrence  
　　Γ\_path　怎样枚举与验证实际的生成路径  
　　Γ\_event　怎样调用六类目标事件的见证  
　　Γ\_bind　对象层的绑定键与机器一侧的见证怎样对应  
　　Γ\_read　三值读出、多证书聚合与求解器状态的规则

这五项都在求解开始之前定下：贡献的投影方式、路径的粒度、事件的见证、绑定的键、候选的枚举与聚合规则，都属于冻结的内容。

第三节

基础对象与定义序列

### 3.1 对象的三类来源

本节用到的对象分三类，各自标明性质。

第一类，上游的本体对象。本系统只调用，不重新定义：

　　Law、LawDyn、SourceLawContribution、TargetDynGeneration、SameInteractionBind、LawInteractionBear  
　　L\_S、L\_T、r\_s、c\_S、Z\_ST、e\_T、β\_int

第二类，已有的形式对象。从《律数理式》《律动力数理式》《律动力运行基底构造式》承继，不重新构造：

　　X\_r、Y\_r、u\_r、m\_r、ζ\_r  
　　𝓡、Φ、Step^M\_Prot、Trans\_Prot、WitTrans  
　　a(k)、E^eval\_k、Exec(E\_k)  
　　𝒮( F, L, I )、RolePath、RoleReal、RoleCtx、DynamicRole^M、ΩSupport^M、Bind^M  
　　六类 LawDyn 事件，以及它们现有的实际机制见证

第三类，本篇新设的纯形式辅助对象。下面逐条定义。它们都不是场量，不是本体谓词，不是动力原因，不进入 𝓡 与 Φ 的自变量。

### 3.2 定义序列

以下逐条编号。每条先说它做什么，再给形式。凡是含关系的条目，其性质在第七节逐项申明。

D1　贡献 occurrence 空间

收纳 source 一侧所有可登记的贡献 occurrence。

　　𝒞^occ\_INT

纯形式辅助对象。

D2　贡献 occurrence 记录

为对象层的一份贡献 occurrence 建立机器一侧的记录。

　　ĉ\_S = \[ L\_S, R\_S, ρ\_S, d\_S, r\_s, π^INT\_contrib( ζ\_{r\_s} ) \] ∈ 𝒞^occ\_INT

各字段：

　　R\_S　待核的 source 一侧形式见证候选。它是否属于 𝒮( F\_{r\_s}, L\_S, I\_S )，由 D4 判定  
　　ρ\_S　待核的 realization 候选。它是否合法属于 RoleReal^{RoleCtx}\_{R\_S}( d\_S )，由 D6 判定  
　　d\_S　这份贡献所申报的职责。它是否属于 Rel( L\_S )，由 D6 判定  
　　r\_s　贡献实际发出的源点  
　　π^INT\_contrib　从实际的执行见证中读出这次职责贡献的纯形式投影

本条只登记候选的字段，不断言其成立。字段一写成成员关系，则凡是能构造出的记录都已先满足 D4 与 D6 的核心条件，那两项的负例便无从进入候选集——候选表示会悄悄变成成功表示。因此各成员关系一律留给相应的读出去判。

R\_S 与 ρ\_S 分属两级，按《律组式》的原有层次：先有形式见证一级，再在其下取得这一次职责的具体 realization。二者不并为一名。

ρ\_S 只进入机器一侧的证书，可列入 β^M\_int 与 W\_S，不进入对象层的 β\_int。

ĉ\_S 是机器一侧的记录，对象层的那份 occurrence 仍写作 c\_S。二者由投影相连：

　　π\_c( ĉ\_S ) = c\_S

对象层的 c\_S 按 3.1 第一类只调用不重新定义；本条所定义的是它在机器一侧的表示。

D3　投影值相等不等于同一份 occurrence

分清「读数一样」与「是同一份」。

　　Value( c\_a ) = Value( c\_b )　⇏　c\_a = c\_b

投影值相同的两份贡献，未必是同一份 occurrence。贡献的跨时身份不属于本系统，所以记录中没有 id\_c 一类的字段。

D4　源点资格读出

判断 source 一侧在贡献发出的那一点上，是否具备正式的 Law 资格。

　　SrcLawQual^M( ĉ\_S ) ∈ { 1, 0, ⊥ }

　　1　R\_S ∈ 𝒮( F\_{r\_s}, L\_S, I\_S )  
　　0　F\_{r\_s} 上的解集已完整求得，而 R\_S 不在其中  
　　⊥　r\_s 处的场态不可读，或解集未能在该点上求得

资格在真实的发出源点 r\_s 上判定。本项只判形式解一级；这一次职责的具体 realization ρ\_S 是否合法，由 D6 判。

D5　贡献存在读出

判断实际的执行见证中是否确有这份贡献 occurrence。

　　ContribOcc^M( ĉ\_S ) ∈ { 1, 0, ⊥ }

　　1　r\_s 处的执行见证完整可读，且 π^INT\_contrib 在其上取得该份 occurrence  
　　0　该见证完整可读，而其上没有这份 occurrence  
　　⊥　该见证不可读，或 π^INT\_contrib 在其上无定义

D6　职责归属读出

判断这份贡献是否确实属于 L\_S 的职责承担。

　　SrcDutyAttrib^M( ĉ\_S ) ∈ { 1, 0, ⊥ }

回读沿这条链：

　　R\_S　→　ρ\_S　→　d\_S　→　Rel( L\_S )

　　1　ρ\_S ∈ RoleReal^{RoleCtx}\_{R\_S}( d\_S )，d\_S ∈ Rel( L\_S )，且 DynamicRole^M 确认 R\_S 在该职责域中具有合法的动态角色承担  
　　0　链上各环都可读，而回读不成——例如它只沿承担者的物理通路而不沿职责通路  
　　⊥　链上有一环不可读，或回读所得的职责不唯一

DynamicRole^M 只负责 Law 侧职责角色的合法性，它属于 Law 资格的动力角色支。这一次 occurrence 与 ρ\_S 的对应，由 D5 的执行见证与本项的 occurrence—职责绑定共同确认。

本项不据 DynamicRole^M 单独推出 LawAct：资格侧的角色合法与当前是否在行，分属两层，后者归第一、二篇。

承担者的物理副作用不计入本项，二者的分层依第六节承继的形式见证与物理承载的分层。

D7　第一层读出器

把上面三项合起来，给出第一层的读数。

　　ReadSrcLawContrib^M( ĉ\_S ) = Bind^M\_SRC( SrcLawQual^M, ContribOcc^M, SrcDutyAttrib^M ) ∈ { 1, 0, ⊥ }

其中 Bind^M\_SRC 先查三项是否落在同一组键上，再以零吸收合取取值：

　　Bind^M\_SRC = 0　三项中有一项为 0，或三项所依的键不同一  
　　Bind^M\_SRC = 1　三项都是 1 且键同一  
　　Bind^M\_SRC = ⊥　键同一、无 0，而至少一项为 ⊥；或键的同一本身不可判

所谓键同一，指三项都依同一组 ( L\_S, R\_S, ρ\_S, d\_S, r\_s, ĉ\_S )。Bind^M\_SRC 是第一层读出器内部的良构绑定，它与对象层绑定的分别见 3.3。

D8　实际执行支撑与限制段关系

在机器一侧指出本次交互所涉的那一段已发生的执行。

　　Ẑ\_{e\_T} = ( ζ\_a, …, ζ\_b )

为上游目标事件 e\_T 的实际事件子段 Z\_{e\_T} 在执行记录上的表示，并有 π\_Z( Ẑ\_{e\_T} ) = Z\_{e\_T}。

　　Ẑ\_ST = ( ζ\_p, …, ζ\_q )，　Ẑ\_ST ⪯ Ẑ\_{e\_T}

Ẑ\_ST 是已发生的执行记录的一个连续有序限制段，取自 η。⪯ 是连续有序限制段关系，其性质见 7.2。

对象层的实际生成子段仍写作 Z\_ST，二者由投影相连：

　　π\_Z( Ẑ\_ST ) = Z\_ST

与 D2 同理：对象层的 Z\_ST 只调用，本条所定义的是它在机器一侧的表示。

D9　形式见证路径

在 Z\_ST 之内取出一条供检验的路径。

　　P\_ST = ( ζ\_{r\_0}, …, ζ\_{r\_m} )，　r\_0 \< … \< r\_m，　P\_ST ⪯ Ẑ\_ST

各节点即执行记录的项，记 z\_i ≔ ζ\_{r\_i}。此记法只为行文简便：凡是需索引处写 r\_i，凡是需记录项处写 z\_i 或 ζ\_{r\_i}，二者不混用。

纯形式辅助对象。

D10　实际执行项与血脉连续

先立路径上流转的项的类型，再定相邻两步的边界相接，末立贯穿全路的血脉链——逐边各自相接不足以判承接，必须同一条血脉一路传下去。

先立通用的实际执行项类型：

　　𝒪^act\_INT

其成员记作 o，为执行记录中实际出入于各步的项——它可以是普通的转换结果、介质中的量、门的输出，不必是 Law 一侧的贡献记录。

路径中途容许经过通道、门、介质与非律的转换节点，这些节点上的项就是 o；若要求它们都是 Law 贡献记录，则第十篇所许的 direct 路径反被排除。中途是否另有一条律接管，另由 D11 专查。

每一步的实际出入由 Γ\_path 所定的 provenance 读法给出：

　　Out^M( z\_i ) ⊆ 𝒪^act\_INT　　该步的实际输出项  
　　Arg^M( z\_{i+1} ) ⊆ 𝒪^act\_INT　下一步原生成机制的实际输入项

边界相接读出：

　　InputLink^M( z\_i, z\_{i+1} ) ∈ { 1, 0, ⊥ }

　　1　存在 o\_i ∈ Out^M( z\_i ) ∩ Arg^M( z\_{i+1} )  
　　0　两集都完整读得，而其交为空  
　　⊥　两集之中有一不可读，或项的身份不可判

这一项只管相邻两步的出入是否相接，不管相接的是不是同一条血脉。单凭它逐边合取不足以判承接：各边可以分别由互不相干的项见证。

设第一边由 a 见证，a ∈ Out^M( z\_0 ) ∩ Arg^M( z\_1 )；而 z\_1 另有一个无关的输入 x，其所生的输出是 b，由 a 所生的却是 c；第二边由 b 见证，b ∈ Out^M( z\_1 ) ∩ Arg^M( z\_2 )。两边各自为 1，而 a 的血脉在 z\_1 已断。这是路径内部的拼证。

因此必须另立一项，查每一步之内输入与输出之间是否确有生成关系：

　　ProvStep^M( z\_i ; o^in\_i, o^out\_i ) ∈ { 1, 0, ⊥ }

　　1　该步的实际执行见证表明 o^out\_i 是 o^in\_i 在这一步实际生成或转换所得的相关后继  
　　0　该见证完整可读，而其上确无此生成关系  
　　⊥　该步内部的生成身份不可判

再立两端的锚定：

　　AnchorItem^M( ĉ\_S, o\_0 ) ∈ { 1, 0, ⊥ }　o\_0 是否为 ĉ\_S 所对应的实际输出项  
　　TargetInput^M( o\_m, w\_{e\_T} ) ∈ { 1, 0, ⊥ }　o\_m 是否进入目标事件的机制见证

血脉链：

　　ProvChain^M( ĉ\_S, P\_ST, w\_{e\_T} ) ∈ { 1, 0, ⊥ }

取值为 1，当且仅当存在一串实际执行项

　　( o\_0, o\_1, …, o\_m )

使下列各项都成立：

　　AnchorItem^M( ĉ\_S, o\_0 ) = 1  
　　对各内部步　o\_{i-1} ∈ Arg^M( z\_i )，　o\_i ∈ Out^M( z\_i )，　ProvStep^M( z\_i ; o\_{i-1}, o\_i ) = 1  
　　TargetInput^M( o\_m, w\_{e\_T} ) = 1

若一切这样的串都已查遍而无一成立，取 0；若无成立的串而其中有项不可判，取 ⊥。

于是

　　StepwiseInputContinuity( ĉ\_S, P\_ST, w\_{e\_T} ) ≔ ProvChain^M( ĉ\_S, P\_ST, w\_{e\_T} )

所追踪的是同一条血脉的连续：自 source 的那一项起，经各步的实际生成一路传到目标的机制见证，而不是各边碰巧都有某个项相接。

这里追踪的是 provenance 的连续，不是数值的相等：贡献的数值可以在途中变化，而它的来处不断。

D11　中间的 Law 侧源

判断路径中途是否另有一条 Law 取得了新的源锚。

　　IntermediateLawSource^M( P\_ST, w\_{e\_T} ) ∈ { 1, 0, ⊥ }

其中 w\_{e\_T} 即 D12 当前所查那张证书所用的目标机制见证，由参数传入，不在本项之内另行存在量化。

取值为 1，当且仅当路径内部存在一个索引 r\_i 与一份按 D2 构造的机器记录

　　ĉ\_M = \[ L\_M, R\_M, ρ\_M, d\_M, r\_i, π^INT\_contrib( ζ\_{r\_i} ) \] ∈ 𝒞^occ\_INT

使

　　ReadSrcLawContrib^M( ĉ\_M ) = 1

并且通向该目标见证的后缀确由 ĉ\_M 接管。记该后缀为

　　P^{(i:m)}\_ST = ( ζ\_{r\_i}, …, ζ\_{r\_m} )

接管即

　　ProvChain^M( ĉ\_M, P^{(i:m)}\_ST, w\_{e\_T} ) = 1

其中的 w\_{e\_T} 就是传入的那一个。这时原本通往该见证的 L\_S → L\_T 直接路径被截断。

此处不另取见证。若容许在本项之内另起存在量词，则中途某条律纵然只对别的目标见证有后缀 provenance，也会截掉当前这条通往本见证的直接路径——那是另一种拼证：截断的依据与所截的物不是同一次事件。

两件事必须分清：路径内部出现一条取得贡献资格的律，只是 ReadSrcLawContrib^M( ĉ\_M ) = 1；它是否真的接管了通往目标的后缀，另由上式判。前者成立而后者不成立的，该律只是在途中有所活动，不构成截断。

　　LawAct( L\_M ) = 1　⇏　IntermediateLawSource^M( P\_ST, w\_{e\_T} ) = 1

中途的 Law 有所活动，不等于它取得了新的源锚。本项是路径内部的一项读出，不是新的 LawDyn 事件。

D12　直接生成路径

判断一条已发生的路径，是否把 ĉ\_S 真正带进了目标事件的生成。

　　DirectGenPath^M\_INT( ĉ\_S, P\_ST, w\_{e\_T} ) ∈ { 1, 0, ⊥ }

取值为 1，需同时满足下列五项。五项各有其签名与取值。

　　ActualPath( P\_ST ) ∈ { 1, 0, ⊥ }  
　　　1　各 r\_i 都是 η 的实际索引，且各 ζ\_{r\_i} 都取自 η 的执行记录  
　　　0　其中有一项不在 η 之内——即取自可能路径、重放路径或反事实路径  
　　　⊥　某一项是否在 η 之内不可判

　　SourceAnchor( P\_ST, ĉ\_S ) ∈ { 1, 0, ⊥ }  
　　　1　r\_0 = r\_s，即首项 z\_0 = ζ\_{r\_s} 正是 ĉ\_S 所登记的源点那一步  
　　　0　r\_0 可读而不等于 r\_s  
　　　⊥　r\_0 或 r\_s 不可读

　　StepwiseInputContinuity( ĉ\_S, P\_ST, w\_{e\_T} ) ∈ { 1, 0, ⊥ }　见 D10，即 ProvChain^M：存在一串实际执行项，自 ĉ\_S 所锚的项起，经各步的实际生成一路传至目标的机制见证

　　TargetMechanismEntry( ĉ\_S, P\_ST, w\_{e\_T} ) ∈ { 1, 0, ⊥ }　见 D14，其所用的 P\_ST 与 w\_{e\_T} 即本条所用者

　　IntermediateLawSource^M( P\_ST, w\_{e\_T} ) ∈ { 1, 0, ⊥ }　见 D11，此处要求取 0；其 w\_{e\_T} 即本条所用的同一目标机制见证

五项按零吸收合取：任一项给出与所要求的相反的确定值则 DirectGenPath^M\_INT = 0；五项都合所求则为 1；无相反的确定值而有 ⊥ 则为 ⊥。

这五项是上游「直接」与 TargetDynGeneration 的形式展开。

D13　目标事件证书

确认所申报的那次 LawDyn 事件本身确实成立。

　　TargetEventCert^M( e\_T ) ∈ { 1, 0, ⊥ }

取值来自上游的相邻步读数：Start、Continue、Stop 读 StepAct\_k，Rise、Fall、Migration 读 StepDeg\_k。

　　1　相应读数取所申报的那个值  
　　0　读数为该值以外的确定值  
　　⊥　读数为 ⊥\_A 或 ⊥\_D

六类各自所读见 4.4。

D14　目标机制进入

确认 source 一侧确实进入了这次事件的生成机制。

　　TargetMechEntry^M\_INT( ĉ\_S, P\_ST, w\_{e\_T} ) ∈ { 1, 0, ⊥ }

路径与目标机制见证都由参数传入，不在本项之内另行存在量化——否则同一份证书之内仍可换一条路径或换一份见证来取得 1。

　　1　ProvChain^M( ĉ\_S, P\_ST, w\_{e\_T} ) = 1，即该血脉链的末项 o\_m 落在 w\_{e\_T} 之内  
　　0　该链已查遍而无一成立  
　　⊥　该链之中有项不可判

六类各自的机制见证见 4.4。

D15　第二层读出器

把事件证书与机制进入合起来，给出第二层的读数。

　　ReadTargetDynGen^M( ĉ\_S, P\_ST, e\_T, w\_{e\_T} ) = Bind^M\_T( TargetEventCert^M( e\_T ), TargetMechEntry^M\_INT( ĉ\_S, P\_ST, w\_{e\_T} ) ) ∈ { 1, 0, ⊥ }

Bind^M\_T 保证事件的事实与机制的见证属于同一组 ( L\_T, E\_k, e\_T, Z\_ST )。它是第二层读出器内部的良构绑定。

D16　机器绑定键

在机器一侧记下这一次检验所依的全部键位。六个主位一律由机器量充任，不把对象键作为现成字段搬进来：

　　β^M\_int = ( L\_S, r\_s, ĉ\_S, Ẑ\_ST, L\_T, e\_T ; R\_S, ρ\_S, d\_S, E\_k, w\_{e\_T}, P\_ST )

分号之前为六个主位，与对象键 β\_int 的六位一一对应；分号之后为检验所需的附加字段。

投影只作用于主位：

　　π\_β( β^M\_int ) = ( L\_S, r\_s, π\_c( ĉ\_S ), π\_Z( Ẑ\_ST ), L\_T, e\_T )

于是要求

　　π\_β( β^M\_int ) = β\_int

便是一项实在的检验：它推出 π\_c( ĉ\_S ) = c\_S 与 π\_Z( Ẑ\_ST ) = Z\_ST，即机器一侧所用的记录与段，确实投回对象层所冻结的那一份贡献与那一段执行。

若把 β\_int 作为现成字段塞进机器键，则这一投影恒成立而什么也验不出，机器证书便不再证明自己与对象层对得上。

分号之后的附加字段是纯形式辅助字段，不参与投影，也不进入对象键。

D17　层间绑定读出

确认两层读的是同一次交互。

　　SameInteractionBind^M ∈ { 1, 0, ⊥ }

取值为 1，需要两件事同时成立：

其一，W\_S、P\_ST 与 W\_T 共同引用同一份 β^M\_int——两层所认的是同一个 L\_S、同一个 r\_s、同一份 ĉ\_S、同一段 Ẑ\_ST、同一个 L\_T、同一次 e\_T。

其二，该机器键经投影落在对象层所冻结的键上：

　　π\_β( β^M\_int ) = β\_int

前者挡住两层各认一物的拼证，后者挡住机器一侧自成一套而与对象层脱钩。二者有一不成，本项取 0；有一件不可判则取 ⊥。

本项是对象层 SameInteractionBind 的形式实现。

D18　单张证书

把一次完整的检验打包为一份可查的证书。

　　W\_INT = ( β\_int, β^M\_int, W\_S, P\_ST, W\_T )

其中

　　W\_S = ( ĉ\_S, R\_S, ρ\_S, d\_S, r\_s, SrcLawQual^M, ContribOcc^M, SrcDutyAttrib^M )

即第一层三项读出及其所依的记录与字段；

　　W\_T = ( E\_k, w\_{e\_T}, P\_ST, TargetEventCert^M( e\_T ), TargetMechEntry^M\_INT( ĉ\_S, P\_ST, w\_{e\_T} ) )

即第二层两项读出及其所依的评价段与机制见证。

D19　候选证书集

收纳一次求解中所有待检验的证书。

　　𝒲\_INT( 𝕀\_INT ) = { W\_INT \| W\_INT 良构 }

所谓良构，指下列四项都成立：

　　其一　ĉ\_S ∈ 𝒞^occ\_INT，且其 r\_s 落在 FiniteActualSupport 之内  
　　其二　P\_ST ⪯ Ẑ\_ST，且 Ẑ\_ST ⪯ Ẑ\_{e\_T}  
　　其三　W\_S 与 W\_T 的各字段齐备，类型合于 D18  
　　其四　W\_S、P\_ST 与 W\_T 共同依同一份 β^M\_int，且 π\_β( β^M\_int ) = β\_int

良构只管结构上齐不齐，不管取值。它是候选的证书空间，不是已经成功的证书的集：其中每一份成员可以分别取 1、0 或 ⊥。

D20　读出

给出本系统对这一次交互的最终读数。

　　Read^M\_INT ∈ { 1, 0, ⊥ }

由第五节的聚合规则给出。

### 3.3 三个绑定各管什么

本系统中有三个绑定，各管一件事：

　　Bind^M\_SRC　　　第一层读出器内部，保证 source 一侧各见证属于同一组  
　　Bind^M\_T　　　　第二层读出器内部，保证事件与机制的见证属于同一组  
　　SameInteractionBind^M　两层之间，是对象层绑定纪律的形式实现

前两个是机器一侧的良构条件，属于 3.1 第三类的纯形式辅助对象；只有第三个对应对象层。

第四节

方程与判据

### 4.1 本节给出什么

第三节定义了各个读出，本节给出它们之间怎么合成：两层各自由哪些项合起来，六类事件分别查什么，遇到分叉与汇合怎么办，一张证书怎么求值。

所形式化的是一次已发生的事的读出，因此这些是判据关系，不是演化方程。各读出以已发生的内容为输入而不改变它，都不进入 𝓡 与 Φ 的自变量。

### 4.2 第一层

　　ReadSrcLawContrib^M = Bind^M\_SRC( SrcLawQual^M, ContribOcc^M, SrcDutyAttrib^M )

取值按零吸收的三值合取，见 5.4。

### 4.3 第二层

　　ReadTargetDynGen^M( ĉ\_S, P\_ST, e\_T, w\_{e\_T} ) = Bind^M\_T( TargetEventCert^M( e\_T ), TargetMechEntry^M\_INT( ĉ\_S, P\_ST, w\_{e\_T} ) )

### 4.4 六类目标事件：事件事实与机制进入分列

事件事实与机制进入分属两层，分别由 D13 与 D14 读出，再由 Bind^M\_T 绑定。本节先给两层各自的取值来源，再列六类。

事件事实一侧　TargetEventCert^M 只确认所申报的那次事件本身确实发生，其取值来自上游的相邻步读数：

　　Start、Continue、Stop　　　读 StepAct\_k  
　　Rise、Fall、Migration　　　读 StepDeg\_k

即

　　TargetEventCert^M( e\_T ) = 1　⟺　相应的相邻步读数取所申报的那个值

读数为该值以外的确定值时取 0；读数为 ⊥\_A 或 ⊥\_D 时取 ⊥。

机制进入一侧　TargetMechEntry^M\_INT 只判 ĉ\_S 是否进入该次事件的实际生成机制，其取值来自各类事件自身的机制见证，与上一层所用的读数不同源。

六类的机制见证如下。

　　Start　　　ActArg^μ  
　　Continue　　Exec( E\_k ) 之中的实际续行见证  
　　Stop　　　　C\_e ∈ CutActual^-\_k  
　　Rise　　　　GainAdv^Γ\_k  
　　Fall　　　　LostAdv^Γ\_k  
　　Migration　 Cross^+\_k ∪ Cross^-\_k

逐类的判法：

Start　ĉ\_S 的直接路径需进入这次 Start 的 ActArg^μ。

Continue　ĉ\_S 的直接路径需进入 Exec( E\_k ) 之中实际的续行见证。

Stop　ĉ\_S 的直接路径需进入该切集的生效生成。不要求 ĉ\_S 本身就是切集的成员。

Rise　ĉ\_S 需进入 GainAdv^Γ\_k 之中至少一份实际的见证。

Fall　ĉ\_S 需进入 LostAdv^Γ\_k 之中至少一份实际的见证。

Migration　目标需先满足 profile 不可比，此属事件事实一侧；ĉ\_S 进入 Cross^+\_k 或 Cross^-\_k 之一即可。设

　　MigPlus^M，　MigMinus^M  
　　MigEnter^M = MigPlus^M ∨₃ MigMinus^M

这两项并列，不合并为一个正负号：Migration 所指的是 profile 不可比，没有增减的区分可言。

两层不同源，所以 Bind^M\_T 有事可做：它要求相邻步读数所标定的那次事件、其所在的评价段 E\_k、以及所取的机制见证，三者属于同一次事件，不能分别取自不同处而拼在一起。

本节的分层承自第五篇：该篇以 StepAct\_k 与 StepDeg\_k 给事件事实，另以 ActualMechanism 判机制进入，二者由 SameDynBind 绑定。若把两层合为一层，则「事件发生了，所以某个 source 一定贡献了它」这一误推无从挡住——第十二节所列的六类假阳性正是它的六种形态。

### 4.5 分叉、汇合与无法分辨的混合

分叉　ĉ\_S 分向 P\_1 与 P\_2 时，只要其中至少一条实际的直接路径抵达目标见证，就可以取得目标生成的见证。不要求各分支都抵达。

汇合而输入身份保留　设 Arg^M( y ) = { o\_A, o\_B }，二者同入一个汇合步 y，其输出为 o′。若该步的实际见证能分别给出

　　ProvStep^M( y ; o\_A, o′ ) = 1　与　ProvStep^M( y ; o\_B, o′ ) = 1

则两条血脉都可续下去，各自的 ProvChain^M 可取 1。这里不要求 but-for 意义上的必要性，也不作数值分摊。

汇合而输入身份丢失　若只知 o′ 存在，而无从判定它承继 o\_A 与 o\_B 之中的哪一个，则 ProvStep^M( y ; · , o′ ) = ⊥，血脉链随之取 ⊥，故

　　DirectGenPath^M\_INT = ⊥

这是读不出的值，与对象一侧的零分属两层。本系统在这种情形下不做数值分解，也没有贡献比例一类的量。

### 4.6 单张证书的求值

　　Val( W\_INT ) = ReadSrcLawContrib^M ∧₃ ReadTargetDynGen^M ∧₃ SameInteractionBind^M

∧₃ 是零吸收的三值合取：任一项确定为 0 则结果为 0；三项都为 1 则结果为 1；没有 0 而至少一项为 ⊥ 则结果为 ⊥。

第五节

运行与求解

### 5.1 求解器

本节给出从输入到读数的完整程序：七个步骤怎么走、在多大范围内枚举、多份证书怎么合成一个读数、候选集为空时怎么判。

　　SolveIntBear

它求解的是 Bear，见 1.3。

输入 𝕀\_INT，输出

　　( Read^M\_INT, SolverStatus )

　　Read^M\_INT ∈ { 1, 0, ⊥ }  
　　SolverStatus ∈ { Resolved, Unreadable, OutOfDomain }

### 5.2 七个步骤

一　检查输入与工作域。核对 𝕀\_INT 各项齐备、Γ\_INT 已冻结；不合的返回 OutOfDomain。

二　枚举 source 候选。在冻结的有限实际支撑之内，枚举候选的贡献 occurrence。

三　第一层读出。对每一个候选求 ReadSrcLawContrib^M。

四　读取目标事件见证。按 Γ\_event 调用六类中的一类，求 TargetEventCert^M。

五　枚举实际路径。在 Ẑ\_ST 之内枚举 P\_ST，求 DirectGenPath^M\_INT。

六　组装并求值证书。组成 W\_INT，按 4.6 求 Val。

七　聚合多份证书。按 5.5 得到 Read^M\_INT。

### 5.3 枚举的范围

一切枚举都限制在冻结的有限实际支撑之内。该域定义为

　　FiniteActualSupport( η, e\_T, Γ\_INT ) = { ζ\_r ∈ η \| r ∈ \[ p\_0, q\_0 \] }

其中 \[ p\_0, q\_0 \] 是 Γ\_path 事先冻结的一段有限索引区间，它含 e\_T 所在评价段 E\_k 的全部索引，并向前扩至 Γ\_path 所定的追溯深度。

该区间有限，η 在其上的记录也有限，因此其上可枚举的 ĉ\_S 与 P\_ST 都是有限多的。

血脉链的枚举也是如此。Γ\_path 在该实际执行记录之上，对每一步 z 给出的 Out^M( z ) 与 Arg^M( z ) 都是有限且可枚举的实际执行项集合；P\_ST 既有限，则其上候选的项串 ( o\_0, …, o\_m ) 也有限可枚举。

因此

　　FiniteActualSupport 有限　⇒　P\_ST 有限　⇒　候选血脉链有限

因此 5.2 的七个步骤各自终止。

### 5.4 三值的传播

各读出都是三值。传播按零吸收的规则：确定的 0 优先于 ⊥；没有 0 而有 ⊥ 则为 ⊥；三项全为 1 才是 1。

第三值记的是机器一侧读不出，它与对象一侧的零分属两层，回读时的分别见 8.3。

### 5.5 多份证书的聚合

这里聚合的是存在型的见证：有一份成立的证书就够。所以取

　　Agg\_INT = ∨₃

规则是：

　　Agg\_INT = 1　至少有一份完整的证书取 1  
　　Agg\_INT = 0　候选域已完整求解，并且所有合法候选都为 0  
　　Agg\_INT = ⊥　没有 1，而至少有一个候选未决，或候选的枚举本身不完备

### 5.6 候选集为空的两种情形

候选集为空有两种缘故：一是完整枚举之后确实没有候选；二是读出器或枚举的能力不足，没能枚举出来。两者需要分开判定。

而只查「按协议枚举完了」还不够。一份从一开始就只看一半路径的协议，也能把它自己所定的候选域枚举干净，于是这一项取 1，而真正的见证恰在另一半——据此回读出对象层的 0，就是错的。所以完整性要分两部。

　　EnumComplete\_INT ∈ { 1, 0 }

取值为 1，需要 𝒲\_INT 已按 Γ\_INT 穷尽，并且其中每一份候选都已求得确定的值。这一项管的是机器一侧枚举干净了没有。

　　WitnessCover\_INT ∈ { 1, 0 }

取值为 1，需要：凡是对象层存在的合法组合——SourceLawContribution、TargetDynGeneration 与 SameInteractionBind 三者齐备的——在 𝒲\_INT 之中都至少有一份对应的 W\_INT。这一项管的是协议所定的候选域有没有漏掉真见证。

它不是求解器自己算得出的内部状态，而是形式—对象之间的覆盖完备桥，登记为 G-INT3，见 13.2。

二者合为

　　ReadComplete\_INT = EnumComplete\_INT ∧ WitnessCover\_INT

于是回读的条件是

　　Read^M\_INT = 0 ∧ ReadComplete\_INT = 1　⇒　LawInteractionBear = 0

ReadComplete\_INT = 0 的情形不进入回读。此时它只表示「当前无法证明读出域完整」，不表示 LawInteractionBear = 0。

第六节

耦合关系

本节说明本系统与哪些已成立的形式系统相接，各自取用什么。

### 6.1 与律动力数理式

两套索引、评价段、实际执行及其见证，都从《律动力数理式》承继。Ẑ\_ST 与 P\_ST 落在它的 Exec( E\_k ) 与 ζ\_r 之上，本系统不另造运行系统。

### 6.2 与律动力运行基底构造式

形式见证与物理承载的分层、PathMap 这座桥、DynamicRole 与合法 realization 的实际形态，都从《律动力运行基底构造式》承继。D6 的职责归属之所以能与承担者的副作用分开，正是依靠这一分层。

### 6.3 与律数理式

𝒮( F, L, I ) 与 RolePath、RoleReal、RoleCtx 从《律数理式》承继。D4 的源点资格就在它上面求得。

### 6.4 与同律 DynContrib 的分别

　　DynContrib( B, e )　≠　LawInteractionBear( L\_S, L\_T ; e\_T )

《律动力数理式》的 SourceQual( B, e ; L, I ) 中，B 是同一条目标律 L 的合法承担者或源，问的是同一条律之内某份承担对本律事件的贡献；本系统的 source 是另一份 Law-role 引用 L\_S，问的是跨律的进入。

两者共用实际的执行、事件的见证、生成链的语义与三值证书的纪律，而 SourceQual 的语义不进入本系统。

### 6.5 与身份各篇的分界

本系统读出的是 provenance，不是 identity。物理 root、实际路径的连续、occurrence 记录的相似，对 SameLaw 都不给出取值——那个判据归身份各篇，至今尚未建立。

第七节

关系性质

定义序列中凡是含关系的条目，其性质逐项申明如下。

### 7.1 投影值相等（D3）

自反、对称、传递都成立——它是值上的等价关系。

而它不推出 occurrence 的同一，见 D3。

### 7.2 限制段关系 ⪯（D8、D9）

　　自反　成立，Z ⪯ Z  
　　反对称　成立，互为限制段的两者同一  
　　传递　成立

所以 ⪯ 是偏序。

它是连续有序限制段关系：次序是实际执行本身就有的，因此不用普通的集合包含代替。

### 7.3 D10 各关系

边界相接　InputLink^M

　　有向　是  
　　自反　不申报，一步对它自身不构成相接  
　　对称　不成立  
　　传递　不申报

步内生成　ProvStep^M

　　有向　是，自输入项指向输出项  
　　对称　不成立  
　　传递　不申报。一步之内的生成关系不跨步合成；跨步的承接由 ProvChain^M 给出

源端锚定　AnchorItem^M

类型化的锚定谓词，非二元的等价关系：它查一份贡献记录与一个实际执行项是否相对应。自反、对称、传递对它不适用。

目标进入　TargetInput^M

类型化的进入谓词，查一个实际执行项是否落在目标事件的机制见证之内。自反、对称、传递对它不适用。

血脉链　ProvChain^M

　　有向　是，自 source 的贡献指向目标的机制见证  
　　对称　不成立

### 7.4 直接生成路径（D12）

第十节

形式实现定理

本节证两件事：这套形式系统确实实现了所服务的结构；在可读域之内，读数与结构互相对应。

定理一　M\_IntBear ⊨ S\_IntBear

在上游条件、冻结协议 Γ\_INT，以及 G-INT1 与 G-INT2 的相应可读条件成立时，下列五项成立。本定理不需要 G-INT3，后者只为定理二所需。

其一，SolveIntBear 在冻结的有限实际支撑之内可以执行。

其二，三值的传播合法。

其三，Read^M\_INT = 1 可以逐项读回第十篇的必要结构。

其四，本篇新增的各辅助对象都是纯形式的，不新增本体条件，不新增场量。

其五，各辅助对象不进入底层的运行律。

证明。

其一，由 5.2 与 5.3：七个步骤中每一步所枚举的内容都在 FiniteActualSupport 之内，该域按 Γ\_INT 冻结且有限；其上的 ĉ\_S、P\_ST 与候选血脉链 ( o\_0, …, o\_m ) 都有限可枚举，所以程序终止。

其二，由 4.6、5.4 至 5.6 的规则逐条给出，其中 0 与 ⊥ 的分别没有被压平。

其三，由 8.2 的逐项对应，而第十篇 12.1 的展开式给出三者齐备即 Bear。

其四，由 8.6 的申明与 3.1 第三类的划分。

其五，由 4.1：本篇给出的是判据关系而不是演化方程，各辅助量都不进入运行律。∎

定理二　完备回读

设 LawInteractionBear = 1，且在该实例上 G-INT1、G-INT2 与 G-INT3 都闭合，则存在 W ∈ 𝒲\_INT 使 Val( W ) = 1，因而

　　Read^M\_INT = 1

证明。

由 LawInteractionBear = 1 与第十篇 12.1 的展开式，对象层的三项齐备：有一份贡献 occurrence c\_S 使 SourceLawContribution = 1，有一次进入使 TargetDynGeneration = 1，且二者由同一组 β\_int 绑定。

由 G-INT3 闭合即 WitnessCover\_INT = 1，这一组合在 𝒲\_INT 之中至少有一份对应的 W。由 D19 的良构条件，该 W 的各字段齐备，其 W\_S、P\_ST 与 W\_T 共依同一份机器键 β^M\_int，且 π\_β( β^M\_int ) = β\_int——即该机器键的主位经 π\_c 与 π\_Z 投出的，正是对象层那一份 c\_S 与那一段 Z\_ST。

由 G-INT1 闭合，W 的第一层三项都可读；对象层的 SourceLawContribution = 1 逐项对应 D4、D5、D6  取 1，且三项依同一组键，故 Bind^M\_SRC = 1，即 ReadSrcLawContrib^M = 1。

由 G-INT2 闭合，W 的路径与机制各项都可读；对象层的 TargetDynGeneration = 1 对应 D12 五项与 D13、D14  取 1，其中 D14 与 D11 所用的 P\_ST 与 w\_{e\_T} 即 W 所载的；事件事实与机制进入同属一次事件，故 Bind^M\_T = 1，即 ReadTargetDynGen^M = 1。

SameInteractionBind^M 必须两件事：其一，两层共依同一份 β^M\_int——上段已由 D19 的良构给出；其二，π\_β( β^M\_int ) = β\_int——也由该良构给出。二者既立，故 SameInteractionBind^M = 1。

此处不以「两层所依的对象层键相同」代它：机器键的主位由机器量充任，投影才是实在的检验；只引对象层的键，便绕过了 D16 所立的那一步。

由 4.6，Val( W ) = 1。由 5.5 的存在型聚合，Read^M\_INT = 1。∎

推论一　可读域之内的双向

定理一其三给出正向，定理二给出反向，故在 G-INT1、G-INT2 与 G-INT3 都闭合的可读域之内

　　Read^M\_INT = 1　⟺　LawInteractionBear = 1

推论二　所证止于 Bear

按 1.3 与 8.5，以上两条定理都不推出 Read^M\_INT = 1 ⇒ LawInteraction = 1。

第十一节

击穿

下列八条，任一成立即击穿本系统。前四条针对读出与回读，后四条针对层级与类型。

K-MI1　对应遗漏。第十篇的某一承重项在 M 中没有对应。

K-MI2　归属有误。ReadSrcLawContrib^M = 1，而回读时发现所读的其实是承担者的物理副作用。

K-MI3　目标证书拼凑。不同的事件见证与机制见证被拼成同一份 target 证书，Bind^M\_T 失效。

K-MI4　假路径。可能路径、重放路径或反事实路径冒充实际路径，ActualPath 失效。

K-MI5　直接性误签。确定存在中间的新 Law 侧源边界，而仍然签出 DirectGenPath^M\_INT = 1。

K-MI6　⊥ 被写成 0。provenance 无法判定而返回 0。

K-MI7　凭相关签 1。关键见证无法判定，而凭相关、共时或端点变化返回 1。

K-MI8　越级回读。Read^M\_INT = 1 被直接读成 LawInteraction = 1。

不构成击穿的：一般式的必要性反例，归第十篇；充分向未证，见 1.3 与 8.5；G 未闭合而返回 ⊥，那是 5.4 申报的取值，不是结论失败。

第十二节

六类假阳性检查

事件成立不等于 source 参与。这一条在六类事件上各有其形态，需逐类检查。

　　Start　　两端同时启动，而 source 没有进入目标的 Start 机制  
　　Continue　目标正在续行，而 source 没有参与实际的续行  
　　Stop　　打掉一个冗余的承担者，而实际的 Stop 另有来源  
　　Rise　　目标 Rise，而 source 没有进入 GainAdv^Γ\_k  
　　Fall　　目标 Fall，而 source 没有进入 LostAdv^Γ\_k  
　　Migration　profile 不可比，而 source 没有进入 Cross^+ 或 Cross^-

六例共同说明一件事：

　　EventFact = 1　⇏　TargetDynGeneration = 1

所以 D15 用 Bind^M\_T 把事件证书与机制进入绑在一起，D14 另行检查进入：只取事件证书的，都是假阳性。

### 13.1 H 组

本篇不新增本体 H。各项 H 都按上游的原条件传导：第十篇的 H-INT1 与 H-INT2，以及《律数理式》《律动力数理式》《律动力运行基底构造式》各自的前件。

失败的后果：上游前件若被撤销，则本次任务不进入求解器的对象判定域，求解器返回

　　SolverStatus = OutOfDomain

这一状态与读出的三个取值分属两层：它说的是这次任务根本没有进入可判定域，不是读出器在域内读不出。因此它既不是对象层的 0，也不是 ⊥。三者的分别是

　　OutOfDomain　≠　0　≠　⊥

前者是工作域不成立，中间的是域内读得而不成立，后者是域内读不出。

### 13.2 G 接口

G-INT1　source 贡献 occurrence 可以从实际的 source 执行见证中完整读取。

　　所系　D2、D5、D7

G-INT2　实际的生成图、目标的输入身份与 provenance 信息足以使 DirectGenPath^M\_INT 合法读出。

　　所系　D10、D12、4.5

G-INT3　形式—对象之间的覆盖完备桥：凡是对象层存在的合法组合，在 𝒲\_INT 之中都有一份对应的候选。

　　所系　5.6 的 WitnessCover\_INT、定理二

　　这一项是桥接前件，不是求解器自己算得出的内部状态。求解器可以查 EnumComplete\_INT，因为那只管自己的候选空间枚举干净了没有；而所定的候选域是否覆盖了对象层的全部真见证，需要这座桥，求解器无法凭自身证明自己的语义完备。

三项都是形式回读接口，不承担本体的必要性。

G-INT1 与 G-INT2 的失败按候选局部传播：在某一份候选 W\_i 上未闭合，只使该候选的相应子读出取 ⊥，从而 Val( W\_i ) = ⊥；全局的 Read^M\_INT 仍按 5.5 聚合。因此一处局部读不出不覆盖别处已经取得的确定正证：若另有一份 W\_j 使 Val( W\_j ) = 1，则 Read^M\_INT = 1。只有在没有任何确定的 1、而又有候选未决时，Read^M\_INT 才取 ⊥。

G-INT3 不按候选传播：它未闭合时 WitnessCover\_INT = 0，因而 ReadComplete\_INT = 0，反向回读不成立，见 8.3。

三项未闭合都只使本系统在相应处无法实例化，第十篇对象层的结论不因此失效。
